# 사람과 AI의 역할 분담

> 원칙: **AI는 실행·검증·제안, 사람은 결정·해석·책임.**
> 복잡하거나 반복적인 작업은 AI에게 맡기되, 분석의 방향을 바꾸는 선택은 항상 사람이 한다.
> 이렇게 나누는 이유는 두 가지다. ① 결과의 근거를 사람이 설명할 수 있어야 한다(보고서·면접). ② AI는 그럴듯한 기본값을 고르기 쉬운데, 이 프로젝트의 가치는 바로 그 기본값을 의심한 지점에서 나왔다(단계 0의 30일치 API, 신고×유형 행 구조 등).

---

## 1. 결정 요청 형식

AI가 `[결정]` 지점에 오면 아래 형식으로 묻고 멈춘다.

```
[결정 요청] 제목
- 배경: 지금까지 나온 수치 2~3개
- 선택지: A … / B … / (C …)
- 각 선택지의 장단점: 한 줄씩
- AI 추천: … (이유 한 줄)
- 결정하면 바뀌는 것: 어느 파일·단계에 영향
```

사람은 고르거나, 다른 안을 말하거나, 추가 확인을 요청한다. 결정되면 AI가 `docs/decision_log.md`에 한 줄 초안을 쓰고 사람이 확인한다.

## 2. 단계별 분담

`[결정]` = 사람이 정한다. 체크포인트(A~H)는 런북의 해당 절에 판단 기준이 있다.

### 단계 0 — 사전검증 (완료, 2026-10-01)

| AI | 사람 |
|---|---|
| API 호출 함수, 응답 구조 파악, 매칭률·결측률 계산, 인코딩 변환 | 진행 판정: 단계 2 진행, 단계 3 매일 갱신 가정 (결정 로그 참고) |

### 단계 1A — 데이터 재구축·EDA (`02` 문서)

| AI | 사람 |
|---|---|
| 파일 점검(기간·열 이름·중복), UTF-8 변환, 병합 코드, 파생변수 생성 | `[결정]` 2015~2017 대여소별 파일 처리(반납내역 제외, 날짜별 합산) |
| 연도별 합계 vs 공표치, 1차 마스터와의 차이 목록 | `[결정]` 반기 경계일·이상값 처리 |
| 결측 위치·비율 보고, 보간 후 `wx_imputed` 표시 | `[결정]` 보간 방식과 결측이 많은 변수의 제외 여부 |
| EDA 표·그림 생성(고장률 기준) | `[결정]` 체크포인트 A — 레짐(구조변화) 판정, 학습 구간 조정 여부 |
| 변수 후보표 초안(근거 수치·미래값 가용성) | `[결정]` 체크포인트 B — 변수 목록 확정(`docs/variables_v1.md`) |
| | `[결정]` 개입 이벤트(`events.csv`)·운영 대수 포함 범위 |

### 단계 1B — 고장률 회귀 (`03` 문서)

| AI | 사람 |
|---|---|
| 모형 사다리(M0 OLS → M4 음이항+offset) 적합, HAC 표준오차, 잔차 진단 | `[결정]` 노출 변수: 대여 건수 / 이동거리 / 이용시간 |
| 1차 OLS vs 새 음이항 비교표, 부품별 IRR표·효과 곡선 | `[결정]` 2021년(시각 없음) 처리: 더미 vs 2022년부터 학습 |
| 시차·민감도 반복 실행 | `[결정]` 체크포인트 C — 기상 효과 유지 여부, 부품별 모형, 예측 타깃 |
| | 해석 문장: "전날 비 → 신고율 몇 배"를 어떻게 말할지 |

### 단계 1C — 예측 비교·보고서 (`04` 문서)

| AI | 사람 |
|---|---|
| 평가 하네스(rolling-origin), 나이브 세트, 모델 학습·평가 반복 | `[결정]` 1C-0 과제 정의 표(타깃·원점·정보 집합) 고정 |
| 날씨 시나리오(A 실측 / B 예보 / C 잡음 / D 평년) 실행 | `[결정]` 주 지표(skill, MAE%, pinball, 커버리지) |
| DM 검정, 예측구간 커버리지 계산, 결과표 | `[결정]` 체크포인트 D·E·F |
| 보고서 표·그림 생성 | `[결정]` **테스트 구간 개봉(1C-9) 승인 — 한 번만** |
| 보고서 초안 문단 | 보고서 핵심 메시지와 최종 문장 |

### 단계 2A — 대여이력 적재·개체 패널 (`05` 문서)

| AI | 사람 |

| 월 파일 단위 적재 루프, Parquet 변환, DuckDB 패널 SQL | `[결정]` 범위: 기간 / 자전거 표본 축소 여부 |
| 행 수·누수 점검, 분포 보고 | `[결정]` 헛대여 기준(3분·300m), 수리 추정 기준, 대여소 군집 수 |
| 거리 오류(`dist_bad`) 표시와 보정값 계산 | `[결정]` 원본 ZIP·CSV 삭제 시점 |
| | `[결정]` 체크포인트 G |

### 단계 2B — 개체 위험 모형 (`06` 문서)

| AI | 사람 |
|---|---|

### 단계 3 — 파이프라인·대시보드·제안 (`07~09` 문서)

| AI | 사람 |
|---|---|
| 수집기·스케줄 코드, 장애 재시도, 대시보드 구현 | `[결정]` 실행 환경(내 컴퓨터 / 서버 / GitHub Actions)과 키 관리 |
| 화면 시안, 성능 점검 | `[결정]` 공개 범위와 재식별 위험 판단(시민 조회에 무엇을 보여줄지) |
| 제안서 초안 | `[결정]` 제안 경로·메시지·제출 |

## 3. 이해 확인 (면접 대비)

절차 하나가 끝날 때마다 AI가 질문 2~3개를 낸다. 사람이 먼저 자기 말로 답하고, AI는 그 뒤에 보완한다. 답하기 어려웠던 질문은 `docs/interview_notes.md`에 모은다.

예시
- 왜 고장 건수가 아니라 이용량 대비 신고율을 보나?
- 고장신고 한 행이 신고 1건이 아니라는 걸 어떻게 알았고, 무엇을 바꿨나?
- 음이항 회귀의 offset은 무슨 역할을 하나?
- 나이브 "다음 주 = 지난주"를 왜 비교 기준으로 쓰나?
- 테스트 구간을 마지막에 한 번만 보는 이유는?
