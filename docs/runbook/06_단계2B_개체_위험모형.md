## 목표

1. 자전거 한 대의 **다음 주 신고 위험**을 점수로 만든다. 사용자 요청 5번의 '현재 고장률'에 해당한다.
2. 그 점수가 단순 기준(많이 탄 자전거, 최근 신고된 자전거 등)보다 **점검 대상을 더 잘 고르는지** 증명한다.
3. 무엇이 위험을 높이는지(누적 거리, 오르막, 비 오는 날 주행, 출퇴근·여가, 재배치 등) 해석한다.
4. 단계 3 서비스가 그대로 쓸 수 있게 점수 산출 명세를 고정한다.

## 2B-0. 문제 정의 (먼저 합의) `[결정]`

| 항목 | 정의 |
|---|---|
| 단위 | 자전거 i, 주 w (월요일 시작) |
| 입력 | w주 끝까지의 상태(05 패널의 설명변수) |
| 라벨 | w+1주의 신고 건수(중복 병합 후). 부품별 라벨도 따로 |
| 핵심 점수 1: **위험률** | 다음 주 1,000km당 기대 신고 건수. 자전거가 '얼마나 닳았나'. 점검 우선순위의 기본값 |
| 핵심 점수 2: 기대 신고 수 | 위험률 × 예상 주행거리(최근 4주 평균). '다음 주에 실제로 신고가 날 자전거'. 현장 수거 관점 |

**왜 위험률(1km당)을 기본으로 하나:** 신고는 누군가 타야 생긴다. 건수만 예측하면 모형이 "많이 탈 자전거"를 고르게 된다. 이것이 1차 분석의 '대여량 예측기' 문제다. 주행거리를 offset으로 두면 같은 거리를 탈 때 누가 더 위험한지를 배운다.

**라벨의 한계(문서·화면에 반드시 적는다):** 신고 ≠ 고장. 실제 수거는 신고의 약 2배다. 모델이 배우는 것은 '신고될 위험'이다.

## 2B-2. 평가 함수와 베이스라인 (1일)

> **결과(2026-10-07)**: `py/risk/risk_eval.py`. 검증 기저율 4.1%. 최고 베이스라인 B3(최근 13주 신고) prec@1000 0.082, lift@5% 1.45. 노출만(B1)은 lift 0.55. 상세 `docs/notes/06_위험모형_메모.md`.

K는 점검 여력과 연결한다. 2023년 정비는 약 27만 건(주 약 5,200건)이었다. 예방 점검에 더 쓸 수 있는 여력을 주 500~2,000대로 가정한다.

```python
def at_k(df, score, K):
    """주마다 점수 상위 K대 → 다음 주 신고 비율(precision)과 전체 신고 자전거 중 잡아낸 비율(recall)"""
    rows = []
    for wk, g in df.groupby("wk"):
        top = g.nlargest(K, score)
        hit = (top.y_next > 0).sum()
        rows.append({"precision": hit / K, "recall": hit / max((g.y_next > 0).sum(), 1)})
    return pd.DataFrame(rows).mean()

def rate_lift(df, score, frac=0.05):
    """상위 frac의 1km당 신고율 ÷ 전체 1km당 신고율 (다음 주에 탄 자전거만)"""
    vals = []
    for wk, g in df[df.km_next > 0].groupby("wk"):
        top = g.nlargest(max(int(len(g) * frac), 1), score)
        vals.append((top.y_next.sum() / top.km_next.sum()) / (g.y_next.sum() / g.km_next.sum()))
    return float(np.mean(vals))

def evaluate(df, score):
    r = {"lift@5%": rate_lift(df, score, 0.05), "lift@20%": rate_lift(df, score, 0.20)}
    for K in (500, 1000, 2000):
        s = at_k(df, score, K)
        r[f"prec@{K}"], r[f"recall@{K}"] = s["precision"], s["recall"]
    return r
```

## 2B-3. 주력 모형 — LightGBM 포아송 + 주행거리 offset (3~4일)

> **결과(2026-10-07)**: `py/risk/risk_lgb.py`. 검증 prec@1000 위험률 0.091(B3 +11%), 기대 신고 수 0.110(+35%); lift@5% 3.5. 부품별 모두 베이스라인 초과. 격자는 둔감. 상세 `docs/notes/06_위험모형_메모.md`.

```python
import lightgbm as lgb, json

FEATS = [
  # 이번 주 이용
  "km", "n_trips", "minutes", "speed_med", "speed_sd",
  # 어떻게 탔나 (비율·강도: '얼마나'가 아니라 '어떻게')
  "sh_commute", "sh_leisure", "sh_round", "sh_rain", "sh_wet", "sh_hot", "sh_cold",
  "climb_per_km", "descent_per_km", "reloc_per_trip",
  # 얼마나 닳았나
  "km_since_rep", "trips_since_rep", "climb_since_rep", "days_since_rep",
  "rain_days_since_rep", "freeze_days_since_rep", "age_days", "km_total",
  # 이력·신호
  "rep_13w", "km_4w", "sham_2w", "left_censored", "last_repaired",
  # 기타
  "bike_type", "month",
]

def prep(df):
    df = df.copy()
    df["climb_per_km"]   = df.climb_m / df.km.where(df.km > 0)
    df["descent_per_km"] = df.descent_m / df.km.where(df.km > 0)
    df["reloc_per_trip"] = df.n_reloc / df.n_trips.where(df.n_trips > 0)
    df["month"] = df.wk.dt.month
    df["bike_type"] = df.bike_type.astype("category")
    return df

panel = prep(panel)
tr = panel[(panel.split == "train") & (panel.km_next > 0)]
va = panel[(panel.split == "valid") & (panel.km_next > 0)]

dtr = lgb.Dataset(tr[FEATS], label=tr.y_next, init_score=np.log(tr.km_next))       # offset
dva = lgb.Dataset(va[FEATS], label=va.y_next, init_score=np.log(va.km_next), reference=dtr)
params = dict(objective="poisson", learning_rate=0.05, num_leaves=63, min_data_in_leaf=500,
              feature_fraction=0.8, bagging_fraction=0.8, bagging_freq=1, lambda_l2=1.0,
              seed=42, verbose=-1)
model = lgb.train(params, dtr, num_boost_round=5000, valid_sets=[dva],
                  callbacks=[lgb.early_stopping(200), lgb.log_evaluation(200)])

# offset은 학습에만 쓰이고 예측에는 들어가지 않는다 → raw_score = log(1km당 신고율)
panel["log_rate"] = model.predict(panel[FEATS], raw_score=True)
panel["risk_rate"] = np.exp(panel.log_rate) * 1000                     # 1,000km당
panel["risk_count"] = np.exp(panel.log_rate) * panel.km_4w / 4          # 기대 신고 수
```

- `last_repaired`: 직전 신고 뒤 공백이 48시간 이상이었는지(05의 `repaired_likely`). **공백이 끝난 뒤(다시 대여된 주부터)만 값이 있고, 그 전에는 결측**으로 둔다. 그래야 미래 정보가 섞이지 않는다
- 하이퍼파라미터는 Valid로만 고른다: `num_leaves` {31, 63, 127}, `min_data_in_leaf` {200, 500, 2000}
- 부품별 모형 4개(`y_tire_next` 등)를 같은 방식으로 만든다. 부품별 표본이 적으면 `min_data_in_leaf`를 키운다

### 채점

va = panel[panel.split == "valid"]

## 2B-4. 해석 모형 (2~3일)

> **결과(2026-10-07)**: `py/risk/risk_interpret.py`. H1(마지막 신고 이후 km) **반대**(0.87, 생존 효과), H2 오르막·H3 비 기각, H4 출퇴근 1.13 ~ 1.3배(여가 0.94), H5 재배치 지지(안장 1.23), H6 수리 뒤 0.89(체인 0.75), H7 나이 지지(타이어·페달). 가설 표는 `docs/notes/06`.

예측이 아니라 "무엇이 위험을 높이나"를 말하기 위한 모형이다. 계수를 해석하기 쉽게 선형 모형을 쓴다. 전체가 크면 자전거 5,000대 표본으로 한다.

```python
import statsmodels.api as sm, statsmodels.formula.api as smf

ids = panel.bike_id.drop_duplicates().sample(5000, random_state=42)
ps = panel[panel.bike_id.isin(ids) & (panel.split != "test") & (panel.km_next > 0)].copy()
cols = ["km_since_rep", "climb_per_km", "descent_per_km", "sh_rain", "sh_wet", "sh_commute",
        "sh_leisure", "reloc_per_trip", "age_days"]
ps = ps.dropna(subset=cols)                                    # 이용이 없던 주는 비율 변수가 결측
for c in ["climb_per_km", "descent_per_km", "reloc_per_trip", "age_days"]:
    ps[f"z_{c}"] = (ps[c] - ps[c].mean()) / ps[c].std()        # 표준화: 1 표준편차당 효과로 읽는다
```

### (a) 음이항 + 주행거리 offset + 자전거 단위 군집 표준오차

같은 자전거의 여러 주는 서로 닮았다(체질). 표준오차를 자전거 단위로 묶어(cluster) 계산해 과신을 막는다.

```python
f = ("y_next ~ np.log1p(km_since_rep) + z_climb_per_km + z_descent_per_km + sh_rain + sh_wet"
     " + sh_commute + sh_leisure + z_reloc_per_trip + z_age_days + C(month)")
off = np.log(ps.km_next)
alpha = smf.negativebinomial(f, data=ps, offset=off).fit(disp=0, maxiter=500).params["alpha"]
res = smf.glm(f, data=ps, family=sm.families.NegativeBinomial(alpha=alpha), offset=off) \
         .fit(cov_type="cluster", cov_kwds={"groups": ps.bike_id})
irr = pd.DataFrame({"irr": np.exp(res.params), "lo": np.exp(res.conf_int()[0]),
                    "hi": np.exp(res.conf_int()[1]), "p": res.pvalues})
irr.to_csv("output/tables/risk_irr_nb.csv")
```

### (b) Cox 모형 — 시간축을 '마지막 신고 이후 주행거리'로

각 행(자전거×주)을 "누적 주행거리 start에서 stop까지 관찰한 구간"으로 본다. 신고가 나면 다음 구간은 0km부터 다시 센다.

```python
from lifelines import CoxPHFitter

cp = ps.assign(start=ps.km_since_rep, stop=ps.km_since_rep + ps.km_next,
               event=(ps.y_next > 0).astype(int), age_years=ps.age_days / 365)
cp = cp[cp.stop > cp.start]
use = ["bike_id", "bike_type", "start", "stop", "event", "climb_per_km", "descent_per_km",
       "sh_rain", "sh_wet", "sh_commute", "reloc_per_trip", "age_years"]

cph = CoxPHFitter(penalizer=0.01)
cph.fit(cp[use].dropna(), duration_col="stop", event_col="event", entry_col="start",
        strata=["bike_type"], cluster_col="bike_id")          # 구간 시작점 = entry, 자전거 단위 군집 보정
cph.print_summary()                                            # exp(coef) = 위험비
cph.summary.to_csv("output/tables/risk_hr_cox.csv")
```

- 시간축이 주행거리라서 "같은 거리를 달렸을 때 무엇이 더 위험한가"를 직접 답한다
- 주의: 여기서 `sh_*`는 w주 값이다. 해석을 더 엄밀하게 하려면 05 패널에서 `lead()`로 **다음 주(구간 안)의 주행 특성**을 가져와 쓴다
- 행이 많아 느리면 표본 대수를 줄인다(2,000대)

### 가설 표 (결과를 채운다)

| 가설 | 기대 방향 | 해당 계수 | 결과 |
|---|---|---|---|
| H1 마지막 신고 이후 누적 거리가 길수록 위험 | + | km_since_rep | |
| H2 오르막 주행이 많을수록 체인·페달 위험 | + (체인·페달 모형) | climb_per_km | |
| H3 비·젖은 노면 주행이 많을수록 체인 위험 | + | sh_rain, sh_wet | |
| H4 출퇴근과 여가는 닳는 부품이 다르다 | 부품별 부호 차이 | sh_commute, sh_leisure | |
| H5 재배치(트럭 적재)가 잦을수록 안장·페달·파손 위험 | + | reloc_per_trip | |
| H6 수거·정비된 뒤에는 위험이 초기화된다 | last_repaired = 1이면 − | last_repaired | |
| H7 오래된 자전거일수록 위험 | + | age_days | |

결과가 가설과 반대여도 그대로 적는다. 1차 분석에서 "여가가 더 영향"이라는 가설은 요일 분석에서 반대 방향의 예비 증거가 나왔다.

## 2B-5. 현재 상태 탐지(헛대여 경보) 검증 (1일)

> **결과(2026-10-07)**: `py/risk/risk_alert.py`. 연속 2회(2 ~ 3분) 경보 7,817건, 7일 안 신고 46%(기준선 8.9%의 5.2배), 선행 중앙값 10.6시간. 2026년은 32%.

서울은 자전거별 고장신고를 공개하는 드문 도시라서, 헛대여 신호가 실제 신고로 이어지는지 **정답과 대조해 검증**할 수 있다. 선행 사례(RIDEY)의 자체 주장(신고보다 중앙값 20~25시간 앞섬)을 독립적으로 확인하는 의미도 있다.

```sql
-- 같은 자전거의 연속 두 통행이 모두 헛대여 → 경보. 같은 자전거 24시간 안 중복 경보는 첫 번째만
CREATE OR REPLACE TABLE alerts AS
WITH s AS (
  SELECT bike_id, rent_dt, sham, lag(sham) OVER (PARTITION BY bike_id ORDER BY rent_dt) AS prev_sham
  FROM trips_seq
), a AS (
  SELECT bike_id, rent_dt AS alert_ts,
         lag(rent_dt) OVER (PARTITION BY bike_id ORDER BY rent_dt) AS prev_alert
  FROM s WHERE sham AND prev_sham
)
SELECT bike_id, alert_ts FROM a
WHERE prev_alert IS NULL OR alert_ts - prev_alert > INTERVAL 24 HOUR;

-- 경보 후 7일 안 신고 비율과 선행 시간
SELECT count(*) AS n_alerts,
  avg(CASE WHEN f.reg_ts <= a.alert_ts + INTERVAL 7 DAY THEN 1.0 ELSE 0 END) AS hit_7d,
  median(date_diff('hour', a.alert_ts, f.reg_ts))
    FILTER (WHERE f.reg_ts <= a.alert_ts + INTERVAL 7 DAY) AS median_lead_h
FROM alerts a
ASOF LEFT JOIN fail f ON a.bike_id = f.bike_id AND a.alert_ts <= f.reg_ts;
```

- [ ] 비교 기준: 무작위 통행 뒤 7일 안 신고 비율. 경보의 적중률이 몇 배인가
- [ ] 등록일시가 날짜뿐이면 선행 시간은 '일' 단위로만 말한다
- [ ] 기준 민감도: 헛대여 2분/3분/5분, 연속 2회/3회

## 흔한 함정

- **건수를 그대로 예측한다** → 많이 탈 자전거를 고르는 모형이 된다. 주행거리 offset
- **offset을 넣고 `predict()` 기본값을 쓴다** → 학습 때 offset은 예측에 포함되지 않는다. `raw_score=True`로 log(비율)을 받는다
- **`last_repaired`처럼 신고 이후 정보를 신고 주에 쓴다** → 누수
- **무작위 행 분할(K-fold)** → 같은 자전거·같은 주 정보가 섞인다. 시간 분할만
- **정확도(accuracy)로 평가한다** → 신고 비율이 5% 안팎이라 모두 '신고 없음'으로 찍어도 95%다. precision@K·lift로 본다
- **'안전' 등급을 만든다** → 신고 누락이 많은 데이터로 안전을 보증할 수 없다
