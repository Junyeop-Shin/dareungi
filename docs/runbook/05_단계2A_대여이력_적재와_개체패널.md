## 목표

## 2A-1. 다운로드와 Parquet 변환 (2~3일, 대부분 기다리는 시간)

한 달 파일씩: ZIP에서 한 달치만 꺼내기 → UTF-8 변환(01 문서 0-4의 `to_utf8`) → DuckDB로 표준 이름·타입 변환 → Parquet 저장 → 꺼낸 CSV와 변환본 삭제. 연도 ZIP을 통째로 풀지 않는다(한 해가 풀면 7~8GB).

**단계 0 확인 결과 (2026-10-01):** 2015-09 ~ 2025-12 월별 파일 124개는 모두 같은 17열(자전거번호, 대여일시, 대여 대여소번호, 대여 대여소명, 대여거치대, 반납일시, 반납대여소번호, 반납대여소명, 반납거치대, 이용시간(분), 이용거리(M), 생년, 성별, 이용자종류, 대여대여소ID, 반납대여소ID, 자전거구분), 인코딩 cp949. 2026-01 ~ 06 월별 CSV 6개는 **자전거구분이 빠진 16열**. 열 이름이 같으므로 `schema_map.csv`는 두 줄 묶음(17열용, 16열용)이면 된다.


```python
# py/21_rent_to_parquet.py
from db import connect
con = connect()

FMT = "['%Y-%m-%d %H:%M:%S', '%Y-%m-%d %H:%M']"    # 날짜 형식 후보(단계 0에서 확인한 것만 남긴다)

def to_parquet(csv_path, c):                        # c: schema_map.csv에서 읽은 {표준이름: 원래이름}
    bt = f'"{c["bike_type"]}"' if c.get("bike_type") else "NULL::VARCHAR"   # 2026 파일엔 자전거구분 없음
    sel = f"""
    SELECT
      TRY_CAST(regexp_extract("{c['bike_no']}", '[0-9]+') AS INTEGER) AS bike_id,
      try_strptime("{c['rent_dt']}", {FMT})                        AS rent_dt,
      TRY_CAST("{c['rent_st']}" AS INTEGER)                        AS rent_st,
      try_strptime("{c['rtn_dt']}", {FMT})                         AS rtn_dt,
      TRY_CAST("{c['rtn_st']}" AS INTEGER)                         AS rtn_st,
      TRY_CAST("{c['use_min']}" AS DOUBLE)                         AS use_min,
      TRY_CAST("{c['use_m']}" AS DOUBLE)                           AS use_m,
      {bt}                                                         AS bike_type,
      "{c['user_type']}"                                           AS user_type
    FROM read_csv('{csv_path}', header = true, all_varchar = true)
    """
    con.execute(f"""
      COPY (SELECT *, year(rent_dt) AS y, month(rent_dt) AS m FROM ({sel}) WHERE rent_dt IS NOT NULL)
      TO 'data/processed/rent'
      (FORMAT PARQUET, PARTITION_BY (y, m), OVERWRITE_OR_IGNORE, FILENAME_PATTERN 'part_{{uuid}}')
    """)
```

- `FILENAME_PATTERN 'part_{uuid}'` 덕분에 여러 원본 파일이 같은 월 폴더에 들어가도 서로 덮어쓰지 않는다
- 같은 원본을 두 번 변환하면 중복이 생긴다. 변환한 파일 목록을 `docs/load_log.csv`에 적는다

파일마다 확인
- [ ] 원본 행 수 = 변환 후 행 수 + 날짜 파싱 실패 행 수
- [ ] `bike_id`, `rent_dt` 결측 비율(0에 가까워야 한다)
- [ ] 월별 건수가 공표 이용 건수와 비슷한가

### 2015 ~ 2023-06은 자전거별 요약만

```python
def summarize_year(csv_path, c, year, until="2023-07-01"):
    # until 이전 대여만 요약한다 → 2023년 파일의 하반기는 상세 적재와 겹치지 않게 빠진다
    con.execute(f"""
    INSERT INTO bike_year
    SELECT TRY_CAST(regexp_extract("{c['bike_no']}", '[0-9]+') AS INTEGER) AS bike_id,
           {year} AS y,
           min(try_strptime("{c['rent_dt']}", {FMT})) AS first_dt,
           count(*) AS n_trips,
           sum(TRY_CAST("{c['use_m']}" AS DOUBLE)) / 1000 AS km
    FROM read_csv('{csv_path}', header = true, all_varchar = true)
    WHERE try_strptime("{c['rent_dt']}", {FMT}) < TIMESTAMP '{until}'
    GROUP BY 1
    """)
# 처음 한 번: CREATE TABLE bike_year (bike_id INTEGER, y INTEGER, first_dt TIMESTAMP, n_trips BIGINT, km DOUBLE)
```

### 실행 루프: 한 달치씩 꺼내 처리

2015-09 ~ 2023-06은 `summarize_year`, 2023-07 이후는 `to_parquet`으로 보낸다. 이미 처리한 파일은 `docs/load_log.csv`로 건너뛰므로 중간에 멈춰도 다시 실행하면 이어서 한다.

```python
# py/21_rent_to_parquet.py 아래쪽에 이어 붙인다 (프로젝트 폴더에서 python py/21_rent_to_parquet.py로 실행)
import shutil, zipfile, csv
from pathlib import Path
from prep import to_utf8      # 01 문서 0-4의 sniff·_best_guess·_copy·to_utf8을 py/prep.py로 옮겨 둔다
ROOT = Path(".")             # 스크립트는 프로젝트 폴더에서 실행하므로 현재 폴더 = 프로젝트 폴더

# 열 이름이 전 기간 같다(단계 0 확인). 2026 파일만 자전거구분이 없다
C17 = dict(bike_no="자전거번호", rent_dt="대여일시", rent_st="대여 대여소번호", rtn_dt="반납일시",
           rtn_st="반납대여소번호", use_min="이용시간(분)", use_m="이용거리(M)",
           user_type="이용자종류", bike_type="자전거구분")
C16 = {**C17, "bike_type": None}

LOG = ROOT / "docs/load_log.csv"
done = set()
if LOG.exists():
    done = {r["file"] for r in csv.DictReader(open(LOG, encoding="utf-8"))}

def log_done(name, how):
    new = not LOG.exists()
    with open(LOG, "a", encoding="utf-8", newline="") as fh:
        w = csv.writer(fh)
        if new:
            w.writerow(["file", "how"])
        w.writerow([name, how])

def process(csv_path, name, c):
    yymm = name[-8:-4]                                   # '..._2306.csv' → '2306'
    if yymm < "2307":
        summarize_year(csv_path, c, 2000 + int(yymm[:2]))
        return "summary"
    to_parquet(csv_path, c)
    return "detail"

tmp = ROOT / "data/interim/rent_csv"; tmp.mkdir(parents=True, exist_ok=True)
raw, utf = tmp / "month_raw.csv", tmp / "month_utf8.csv"

# 1) 연도 ZIP(2015~2025): 한 달치씩 꺼낸다. 통째로 풀지 않는다
for z in sorted((ROOT / "data/raw/rent_history").glob("*.zip")):
    with zipfile.ZipFile(z) as zf:
        for m in zf.infolist():
            name = m.filename if m.flag_bits & 0x800 else m.filename.encode("cp437").decode("cp949")
            if not name.lower().endswith(".csv") or name in done:
                continue
            with zf.open(m) as src, open(raw, "wb") as dst:
                shutil.copyfileobj(src, dst)             # 한 달치(최대 약 0.8GB)만 디스크에
            to_utf8(raw, utf)
            log_done(name, process(utf.as_posix(), name, C17))
            raw.unlink(); utf.unlink()
            print("완료", name)

# 2) 2026 월별 CSV: 자전거구분 없음 → C16
for f in sorted((ROOT / "data/raw/rent_history").glob("*.csv")):
    if f.name in done:
        continue
    to_utf8(f, utf)
    log_done(f.name, process(utf.as_posix(), f.name, C16))
    utf.unlink()
    print("완료", f.name)
```

- 처음 실행 전에 `CREATE TABLE bike_year ...`를 한 번 실행한다
- 시간이 오래 걸린다(월 파일 하나에 1~3분 × 130개). 노트북 대신 터미널에서 `python py/21_rent_to_parquet.py`로 돌리면 VS Code를 닫아도 계속된다
- 원본 ZIP·CSV는 이 루프가 끝나고 `load_log.csv`에 130개가 모두 적힌 것을 확인한 뒤에 지울지 정한다(다시 받으려면 오래 걸린다)

2026년 4월 재등록 이후 2015년 파일도 17열 전부가 있다(단계 0 확인). 요약에는 자전거번호·대여일시·이용거리만 쓴다.

2026년 파일의 `bike_type`은 NULL로 들어간다. 2A-5의 `mode(t.bike_type)`는 NULL을 건너뛰므로 2025년 이전에 한 번이라도 탄 자전거는 그때 종류로 채워진다. 2026년에 새로 들어온 자전거만 비는데, 07의 API 수집분(`BIKE_SE_CD`)이나 '운영 자전거 정보' 데이터셋으로 채운다.

## 2A-2. 정제와 표시(flag) (1일)

지우지 말고 **표시**한다. 짧은 대여는 고장 신호라서 버리면 안 된다.

```sql
CREATE OR REPLACE TABLE trips AS
SELECT DISTINCT ON (bike_id, rent_dt, rent_st) *,
  (rtn_dt IS NULL OR rtn_dt < rent_dt)                   AS bad_time,
  use_m / 1000.0 / NULLIF(use_min / 60.0, 0)             AS speed_kmh,
  (rent_st = rtn_st AND use_min <= 3 AND use_m <= 300)   AS sham,        -- 헛대여 후보
  (rent_st = rtn_st AND use_min > 3)                     AS round_trip,  -- 왕복(루프형)
  ((use_m = 0 AND rent_st <> rtn_st)                                      -- 다른 대여소인데 거리 0 = 기록 누락
   OR use_m / 1000.0 / NULLIF(use_min / 60.0, 0) > 35)  AS dist_bad      -- 단계 0: 2026-01 기준 약 1%
FROM trips_raw
WHERE bike_id IS NOT NULL;
```

확인하고 `docs/panel_dictionary.md`에 적을 숫자
- [ ] 완전 중복 제거 건수
- [ ] `bad_time` 비율
- [ ] 이용시간·거리·속도 중앙값과 99% 값(연도별로 튀는지)
- [ ] `dist_bad` 비율(단계 0의 2026-01: 다른 대여소인데 0 = 0.97%, 35km/h 초과 = 0.06%). 연도별로 크게 다르면 기록
- [ ] `dist_bad` 행의 거리는 버리지 않고 채운다: 대여소 좌표(2A-3의 대여소 정보)로 직선거리를 구하고, 정상 행에서 '실제 거리 ÷ 직선거리'의 중앙값(보통 1.2~1.5)을 곱한다. 좌표가 없으면 이용시간 × 중앙 속도(약 8.7km/h). 채운 값은 `use_m_fixed`로 따로 둔다
- [ ] 헛대여 비율, 왕복 비율
- [ ] `user_type` 값별 건수. 직원 이동·정비 이동으로 보이는 코드가 있으면 분석에서 뺀다
- [ ] `bike_type` 값별 대수(일반, 새싹 등)

헛대여 기준(3분·300m)은 외부 선례를 따른 것이다. 분포를 보고 2분/5분으로 바꿔 보는 민감도 분석을 06에서 한다.

## 2A-3. 대여소 테이블과 고도 (1~2일)

### 대여소 마스터

- 대여소 정보(OA-13252, API `tbCycleStationInfo`)와 대여소 마스터(OA-21235, API `bikeStationMaster`)를 받는다
- 폐쇄된 옛 대여소가 최신 목록에 없을 수 있다. 가능한 여러 시점의 목록을 합친다
- 표준 열: `st_no`(정수, 대여이력의 대여소번호와 같은 체계), `st_name`, `lat`, `lon`, `district`(주소에서 '○○구' 추출), `han_river`(0/1)

```sql
CREATE OR REPLACE TABLE station AS
SELECT * FROM read_csv('data/interim/station_master.csv', header = true);

SELECT avg(CASE WHEN s.st_no IS NULL THEN 1.0 ELSE 0 END) AS unknown_rent_st
FROM trips t LEFT JOIN station s ON t.rent_st = s.st_no;     -- 목표: 1% 미만
```

- [ ] 좌표를 못 찾은 대여소가 대여 건수 기준 1% 미만인가. 넘으면 옛 목록을 더 찾는다
- [ ] `han_river`: 이름에 '한강'이 들어가거나 한강공원 안에 있는 대여소. 이름 규칙으로 뽑은 뒤 지도로 눈 검수

### 고도 (OpenTopoData 무료 API)

요청당 100지점, 초당 1회, 하루 1,000회 제한이다. 대여소 약 2,800곳이면 28회로 끝난다.

```python
# py/23_elevation.py
import time, requests, pandas as pd
st = pd.read_csv("data/interim/station_master.csv")
elev = []
for i in range(0, len(st), 100):
    chunk = st.iloc[i:i + 100]
    loc = "|".join(f"{a},{b}" for a, b in zip(chunk.lat, chunk.lon))
    r = requests.get("https://api.opentopodata.org/v1/srtm30m", params={"locations": loc}, timeout=60)
    r.raise_for_status()
    elev += [x["elevation"] for x in r.json()["results"]]
    time.sleep(1.1)
st["elev_m"] = elev
st.to_csv("data/interim/station_master.csv", index=False)
```

확인
- [ ] 남산·관악산·북한산 근처 대여소가 높고, 한강변이 10~20m 안팎인지 10곳 눈 검수
- [ ] 30m 격자라 도심 건물 영향이 있다. **절대 고도가 아니라 대여소 간 차이**로 쓴다는 점을 한계에 적는다
- [ ] (선택) 국토지리정보원 DEM으로 바꿔 차이를 본다

## 2A-4. 출발·도착 쌍(OD) 지형표 (반나절)

실제 경로는 모른다. 알 수 있는 것은 출발·도착 대여소뿐이다. 그래서 **실제로 등장한 OD 쌍**에 대해서만 직선거리와 고도차를 계산한다.

```sql
CREATE OR REPLACE TABLE od AS
WITH pairs AS (SELECT rent_st, rtn_st, count(*) AS n FROM trips GROUP BY ALL)
SELECT p.rent_st, p.rtn_st, p.n,
  2 * 6371000 * asin(sqrt(
      pow(sin(radians(b.lat - a.lat) / 2), 2) +
      cos(radians(a.lat)) * cos(radians(b.lat)) * pow(sin(radians(b.lon - a.lon) / 2), 2))) AS straight_m,
  b.elev_m - a.elev_m AS delta_elev
FROM pairs p
JOIN station a ON p.rent_st = a.st_no
JOIN station b ON p.rtn_st = b.st_no;
```

파생: 오르막 `climb_m = max(Δ고도, 0)`, 내리막 `descent_m = max(−Δ고도, 0)`, 우회율 `detour = 이용거리 ÷ 직선거리`.

- **오르막과 내리막을 합치지 않는다.** 오르막은 체인·페달에 큰 힘, 내리막은 제동·타이어 쪽이라 합치면 정보가 사라진다
- 왕복(A→A)은 고도차 0이지만 거리는 길다. '평지'로 오해하지 않도록 왕복 여부를 따로 표시한다(2A-2의 `round_trip`)
- 검증: 자치구별 평균 오르막(관악·종로·성북 vs 강서·송파)이 상식과 맞는지

## 2A-6. 주행 구분 (1~2일)

### 대여소 성격 군집 (학습 기간 자료로만)

대여소마다 요일×시간 168칸의 대여 비율과 반납 비율(합쳐 336차원)을 만들어 군집한다.

```python
# py/26_station_clusters.py
import pandas as pd
from sklearn.cluster import KMeans
from db import connect
con = connect()
prof = con.execute("""
  SELECT st, dir, isodow(ts) * 100 + hour(ts) AS slot, count(*) AS n FROM (
    SELECT rent_st AS st, 'out' AS dir, rent_dt AS ts FROM trips WHERE rent_dt < TIMESTAMP '2025-07-01'
    UNION ALL
    SELECT rtn_st, 'in', rtn_dt FROM trips WHERE rtn_dt < TIMESTAMP '2025-07-01'
  ) GROUP BY ALL
""").df()
wide = prof.pivot_table(index="st", columns=["dir", "slot"], values="n", fill_value=0)
share = wide.div(wide.sum(axis=1), axis=0)
km = KMeans(n_clusters=5, random_state=42, n_init=10).fit(share.to_numpy())
pd.DataFrame({"st_no": share.index, "cluster": km.labels_}).to_csv("data/interim/station_cluster.csv", index=False)
```

군집마다 평균 프로파일을 그려 이름을 붙인다.
- 평일 출근 시간 **반납** 초과 → 업무지구
- 평일 출근 시간 **대여** 초과 → 주거지
- 주말 낮·왕복 집중 → 여가(한강·공원)
- 지하철 인접·단거리 → 환승

- [ ] 군집 수 4~6에서 해석이 가장 선명한 것을 고르고 결정 로그에 적는다
- [ ] 김희수·김영호(2020)의 결과(여의도 출근 유입, 주말 한강 이용 등)와 대체로 맞는지 본다
- [ ] 군집은 학습 기간(2025-06까지)으로만 만든다. 테스트 기간 정보가 섞이지 않게

```sql
CREATE OR REPLACE TABLE trips_x AS
SELECT t.*,
  (isodow(t.rent_dt) <= 5 AND h.date IS NULL
     AND (hour(t.rent_dt) BETWEEN 7 AND 9 OR hour(t.rent_dt) BETWEEN 17 AND 19)
     AND NOT t.round_trip)                                                   AS commute,
  (isodow(t.rent_dt) >= 6 OR h.date IS NOT NULL OR t.round_trip
     OR sa.han_river = 1 OR sb.han_river = 1)                                AS leisure,
  o.straight_m, o.delta_elev,
  greatest(o.delta_elev, 0)  AS climb_m,
  greatest(-o.delta_elev, 0) AS descent_m,
  t.use_m / NULLIF(o.straight_m, 0) AS detour,
  w.temp, w.rain_mm AS rain_now, w.rain_prev3h
FROM trips t
LEFT JOIN od o        USING (rent_st, rtn_st)
LEFT JOIN station sa  ON t.rent_st = sa.st_no
LEFT JOIN station sb  ON t.rtn_st  = sb.st_no
LEFT JOIN holidays h  ON CAST(t.rent_dt AS DATE) = h.date
LEFT JOIN wx_h w      ON date_trunc('hour', t.rent_dt) = w.ts;
```

### 자전거 궤적 사건 (재배치, 대기 시간)

```sql
CREATE OR REPLACE TABLE trips_seq AS
SELECT *,
  prev_rtn_st IS NOT NULL AND rent_st <> prev_rtn_st AS relocated,     -- 사용자 없이 옮겨짐(트럭 재배치·정비 수거)
  date_diff('hour', prev_rtn_dt, rent_dt)            AS idle_h
FROM (
  SELECT *,
    lag(rtn_st) OVER w AS prev_rtn_st,
    lag(rtn_dt) OVER w AS prev_rtn_dt
  FROM trips_x
  WINDOW w AS (PARTITION BY bike_id ORDER BY rent_dt)
);
```

- 1억 건 전체에 창 함수를 한 번에 돌리면 오래 걸린다. 느리면 연도별로 나눠 돌리고, 앞 연도 마지막 통행을 붙여 경계를 잇는다
- [ ] 재배치 비율이 상식적인지(보도: 연 수십만 건 규모). 너무 높으면 대여소 번호 체계 불일치를 의심한다

### 신고 위치: 신고 직전 마지막 반납 대여소

CREATE OR REPLACE TABLE fail_loc AS
SELECT f.*, t.rtn_st AS last_st, t.rtn_dt AS last_rtn_dt
FROM fail f
ASOF LEFT JOIN trips t
  ON f.bike_id = t.bike_id AND f.reg_ts >= t.rtn_dt;

### 수리 추정: 신고 후 다음 대여까지의 공백

```sql
CREATE OR REPLACE TABLE fail_gap AS
SELECT f.*, n.rent_dt AS next_rent_dt,
       date_diff('hour', f.reg_ts, n.rent_dt) AS gap_h
FROM fail_loc f
ASOF LEFT JOIN trips n
  ON f.bike_id = n.bike_id AND f.reg_ts <= n.rent_dt;
```

- [ ] `gap_h` 히스토그램(로그 축)을 그린다. 두 봉우리(몇 시간 = 계속 운행 / 며칠 = 수거·정비)가 보이면 골짜기를 기준으로 `repaired_likely`를 정한다(예: 48시간 이상)

- [ ] 신고의 몇 %가 위치를 얻었는가(= 신고 전 대여 기록이 있는 비율)
- [ ] 자치구별 신고 수를 지도로 그려 본다. 단계 3의 자치구 단위 예측이 여기서 가능해진다

```sql
CREATE OR REPLACE TABLE panel0 AS
WITH span AS (SELECT bike_id, min(wk) AS w0, max(wk) AS w1 FROM bw_usage GROUP BY bike_id),
     weeks AS (SELECT DISTINCT wk FROM bw_usage)
SELECT s.bike_id, w.wk,
  coalesce(u.n_trips, 0) AS n_trips, coalesce(u.km, 0) AS km, coalesce(u.minutes, 0) AS minutes,
  u.sh_commute, u.sh_leisure, u.sh_round, u.sh_rain, u.sh_wet, u.sh_hot, u.sh_cold,
  coalesce(u.climb_m, 0) AS climb_m, coalesce(u.descent_m, 0) AS descent_m,
  u.speed_med, u.speed_sd,
  coalesce(u.n_reloc, 0) AS n_reloc, coalesce(u.n_sham, 0) AS n_sham,
  coalesce(f.n_rep, 0) AS n_rep, coalesce(f.n_tire, 0) AS n_tire, coalesce(f.n_chain, 0) AS n_chain,
  coalesce(f.n_saddle, 0) AS n_saddle, coalesce(f.n_pedal, 0) AS n_pedal,
  coalesce(f.repaired_likely, 0) AS repaired_likely,
  x.rain_days, x.freeze_days
FROM span s
JOIN weeks w ON w.wk BETWEEN s.w0 AND s.w1
LEFT JOIN bw_usage u ON u.bike_id = s.bike_id AND u.wk = w.wk
LEFT JOIN bw_fail  f ON f.bike_id = s.bike_id AND f.wk = w.wk
LEFT JOIN wx_w     x ON x.wk = w.wk;
```

### (4) '마지막 신고 이후' 누적과 라벨

신고가 있던 주마다 구간 번호(`seg`)를 새로 매긴다. 같은 구간 안에서 누적하되, 신고가 있던 주의 값은 빼서 '신고 다음 주부터' 세게 한다.

```sql
CREATE OR REPLACE TABLE panel AS
WITH a AS (
  SELECT *,
    sum(CASE WHEN n_rep > 0 THEN 1 ELSE 0 END)
      OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS seg
  FROM panel0
)
SELECT *,
  CASE WHEN seg = 0 THEN sum(km) OVER s ELSE sum(km) OVER s - first_value(km) OVER s END            AS km_since_rep,
  CASE WHEN seg = 0 THEN sum(n_trips) OVER s ELSE sum(n_trips) OVER s - first_value(n_trips) OVER s END AS trips_since_rep,
  CASE WHEN seg = 0 THEN sum(climb_m) OVER s ELSE sum(climb_m) OVER s - first_value(climb_m) OVER s END AS climb_since_rep,
  CASE WHEN seg = 0 THEN sum(rain_days) OVER s ELSE sum(rain_days) OVER s - first_value(rain_days) OVER s END AS rain_days_since_rep,
  CASE WHEN seg = 0 THEN sum(freeze_days) OVER s ELSE sum(freeze_days) OVER s - first_value(freeze_days) OVER s END AS freeze_days_since_rep,
  -- 직전 신고의 수리 추정값: 신고 뒤 다시 대여된 뒤(공백이 끝난 뒤)부터만 값이 있다
  CASE WHEN seg > 0 AND sum(n_trips) OVER s - first_value(n_trips) OVER s > 0
       THEN first_value(repaired_likely) OVER s END                                               AS last_repaired,
  sum(km) OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW) AS km_cum,
  seg = 0                                                                                         AS left_censored,
  date_diff('day',
    max(CASE WHEN n_rep > 0 THEN wk END)
      OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW), wk) AS days_since_rep,
  sum(n_rep) OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN 12 PRECEDING AND CURRENT ROW)     AS rep_13w,
  sum(km)    OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN 3 PRECEDING AND CURRENT ROW)      AS km_4w,
  sum(n_sham) OVER (PARTITION BY bike_id ORDER BY wk ROWS BETWEEN 1 PRECEDING AND CURRENT ROW)     AS sham_2w,
  lead(n_rep)    OVER (PARTITION BY bike_id ORDER BY wk) AS y_next,
  lead(n_tire)   OVER (PARTITION BY bike_id ORDER BY wk) AS y_tire_next,
  lead(n_chain)  OVER (PARTITION BY bike_id ORDER BY wk) AS y_chain_next,
  lead(n_saddle) OVER (PARTITION BY bike_id ORDER BY wk) AS y_saddle_next,
  lead(n_pedal)  OVER (PARTITION BY bike_id ORDER BY wk) AS y_pedal_next,
  lead(km)       OVER (PARTITION BY bike_id ORDER BY wk) AS km_next
FROM a
WINDOW s AS (PARTITION BY bike_id, seg ORDER BY wk ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW);
```

- `seg = 0`(관측 시작 후 아직 신고가 없던 구간)은 그 전 이력을 모른다. `left_censored`로 표시하고, **2023년 하반기 준비 기간 덕분에 2024년 이후 행에서는 이 비율이 줄어든다**
- 이 행 이후의 값은 전부 `wk` 주 끝까지의 정보다. 라벨만 `lead()`로 다음 주 값이다

### (5) 나이, 누적 전체 거리, 차종 붙이기

CREATE OR REPLACE TABLE bike_info AS

## 2A-10. 패널 점검 — 체크포인트 G `[결정]`

| 점검 | 기대값 | 벗어나면 |
|---|---|---|
| 행 수 | 약 4만~4.5만 대 × 약 130주 ≈ 550만 | 격자 생성 확인 |
| 다음 주 신고가 1건 이상인 행 비율 | 약 3~8% (2025년 신고 약 11만 건 ÷ 약 4만 대 ÷ 52주 ≈ 5%) | 라벨 결합·중복 병합 확인 |
| 패널에 들어간 신고 비율 | 단계 0 매칭률과 비슷 | 번호 정규화 확인 |
| `km_since_rep` 분포 | 오른쪽으로 긴 꼬리, 음수 없음 | 구간 계산 확인 |
| 이용이 0인 주 비율 | 정비·보관 중인 자전거. 10~20% 안팎이면 자연스럽다 | 격자 범위 확인 |
| `left_censored` 비율 | 2024년 초에 높고 점점 감소 | 준비 기간 길이 확인 |

**누수 점검(가장 중요)**
- [ ] 모든 설명변수가 해당 주 끝까지의 정보만 쓰는가(창 함수가 `CURRENT ROW`에서 끝나는가)
- [ ] 라벨(`y_next`)만 다음 주 값인가
- [ ] 대여소 군집이 학습 기간 자료로만 만들어졌는가
- [ ] `repaired_likely`는 신고 **이후** 공백으로 계산된다. 신고 주의 행에서 이 값을 설명변수로 쓰면 미래 정보가 섞인다 → 06에서 '직전 신고의 수리 여부'로 쓸 때는 공백이 끝난(다시 대여된) 뒤의 주부터만 쓴다

`docs/panel_dictionary.md`에 변수마다 [이름, 정의, 계산 창, 단위, 결측 의미]를 적는다.

## 흔한 함정

- **CSV를 한꺼번에 풀어 디스크가 찬다** → 한 파일씩 변환하고 지운다
- **짧은 대여를 이상치로 지운다** → 헛대여는 핵심 신호다. 표시만 한다
- **대여소 번호 체계가 해마다 다르다** → 숫자형 번호와 `ST-` ID를 섞지 않는다. 단계 0 매핑표대로
- **오르막·내리막을 합쳐 '고도차'로만 쓴다** → 정보가 사라진다
- **군집·기준값을 전체 기간으로 만든다** → 테스트 누수. 학습 기간으로만
- **메모리 부족으로 DuckDB가 멈춘다** → `memory_limit`을 낮추고 `temp_directory`를 지정한다. 창 함수는 연도별로 나눈다
