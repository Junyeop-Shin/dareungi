# 00. 로드맵과 공통 규칙

> 이 폴더의 md 파일만 보고 프로젝트를 끝까지 진행할 수 있게 만든 실행 문서(런북)다.
> **파일 번호 = 작업 순서.** 각 파일은 같은 구조로 되어 있다.
> 목표 → 선행 조건 → 준비물 → 절차(할 일·방법·확인) → 체크포인트(판단 기준과 분기) → 흔한 함정 → 완료 기준.
>
> 작성 기준일: 2026-09-28. 데이터 공개 주기와 API 사양은 바뀔 수 있으니 단계 0에서 다시 확인한다.

## 1. 프로젝트 한 줄 정의

공개 데이터로 따릉이 **이용자 고장신고**를 (i) 부품×주 단위로 미리 예측하고, (ii) 자전거별 신고 위험도를 매긴다.
이것으로 서울시설공단의 부품 발주, 정비 인력 배치, 점검 우선순위 결정을 돕는 대시보드를 만들어 제안한다.

### 세 가지 문제를 섞지 않는다

| 구분 | 질문 | 다루는 단계 | 쓰는 사람 |
|---|---|---|---|
| (i) 집계 수요 예측 | 다음 주 타이어 신고는 몇 건인가? | 단계 1 | 정비 관리자(발주·인력) |
| (ii) 개체 위험 | 어떤 자전거가 곧 신고될 가능성이 높은가? | 단계 2 | 순회 정비(점검 순서) |
| (iii) 현재 상태 탐지 | 지금 고장 난 자전거는? (헛대여 신호) | 단계 2·3 보조 | 현장·시민 |

### 종속변수에 대한 약속

- 예측 대상은 실제 '고장'이 아니라 **'이용자 고장신고'**다.
- 실제 수거 대수는 신고의 약 2배다. 신고되지 않는 고장이 많다는 뜻이다.
- 보고서와 대시보드에서는 "고장률" 대신 **"신고율·신고 위험도"**로 표기하거나, 첫 등장 때 정의를 밝힌다.

## 2. 전체 흐름과 일정

```
단계 0 사전검증 ─▶ 단계 1 집계 예측 재수행 ─▶ 단계 2 개체 위험 ─▶ 단계 3 파이프라인·대시보드·제안
 (0.5~2일)          (3~4주)                    (4~6주)             (3~4주)
```

| 파일 | 단계 | 예상 기간 | 끝나면 남는 것 |
|---|---|---|---|
| 01 | 0 사전검증 | 0.5~2일 | 진행 판정표(phase0_result.md) |
| 02 | 1A 데이터 재구축·EDA | 5~6일 | daily_master_v2, 고장률 EDA 표·그림, 확정 변수 목록 |
| 03 | 1B 고장률 회귀 | 4~5일 | 1차 OLS vs 새 NB 비교표, 부품별 발생률비(IRR) |
| 04 | 1C 예측 비교·보고서 | 8~10일 | 나이브 대비 비교표, 예측구간 평가, 최종 보고서 |
| 05 | 2A 대여이력 적재·개체 패널 | 2~3주 | DuckDB, 자전거×주 패널 |
| 06 | 2B 개체 위험 모형 | 1.5~2주 | 위험 점수 모델, 평가 보고서, 점수 산출 명세 |
| 07 | 3A 자동 수집 파이프라인 | 1~1.5주 | 자동 수집·점수 갱신 작업 |
| 08 | 3B 대시보드·시민 조회 | 1~1.5주 | 대시보드 3종 |
| 09 | 3C 서울시 제안 | 3~5일 | 제안서, 데모, 제출 기록 |

합계 10~14주. 재수행에 쓸 수 있다고 잡아 둔 3~4주는 단계 1에 해당한다.

### 단계 간 의존 관계

- 단계 0 결과는 세 곳을 결정한다.
  - 단계 1의 데이터 범위
  - 단계 2 착수 여부(자전거번호 조인 매칭률)
  - 단계 3의 갱신 주기(고장신고 API가 며칠 늦게 나오는지)
- 고장신고 원자료에는 **위치가 없다.** 단계 2에서 '신고 직전 마지막 반납 대여소'를 붙여야 자치구·센터 단위 예측이 가능해진다. 그래서 단계 1은 서울시 전체 단위로만 한다.
- 단계 1은 단계 2가 실패해도 그 자체로 완결되는 결과물이다. 단계마다 멈춰도 남는 것이 있게 설계했다.

## 3. 공통 규칙 (모든 단계)

1. **원자료는 건드리지 않는다.** `data/raw`는 수정 금지. 모든 가공은 스크립트로 한다.
2. **보고서 숫자는 스크립트가 만든다.** 손으로 옮기는 숫자는 0개. 1차 보고서의 표 3 오류가 재발하지 않도록 표·그림을 전부 스크립트가 파일로 저장한다.
3. **분할은 고정한다(단계 1).**
   - Train: 2020-01-01 ~ 2023-12-31
   - Valid: 2024-01-01 ~ 2024-12-31 (모든 선택은 여기서)
   - Test: 2025-01-01 ~ 2026-06-30 (마지막에 한 번만)
   - **(2026-10-05 체크포인트 A로 변경) Train은 2021-04-08부터.** 2020-05 ~ 2021-03은 신고율 수준이 절반인 기간이라 뺐다. 1B에서 2022-03 시작과 비교한다. 테스트 구간은 다른 레짐으로 보고 모든 예측모형에 최근 4주 신고율을 넣으며, 테스트 결과는 2025 상반기·하반기·2026 상반기로 나눠 보고한다
4. **모든 결과표의 첫 줄은 나이브다.** 나이브를 못 이기면 그것도 결과로 적는다.
5. **결정 로그를 남긴다.** 방향이 바뀔 때마다 `docs/decision_log.md`에 한 줄. 보고서 '시행착오' 절의 재료가 된다.
6. **재현성을 지킨다.**
   - 시드 고정: `random_state=42`, `np.random.default_rng(42)`, LightGBM `seed=42`
   - 패키지 버전 고정: `pip freeze > requirements.txt` (패키지를 추가할 때마다)
   - 데이터 버전: 다운로드 날짜를 파일명이나 기록에 남긴다
   - 노트북은 마지막에 '커널 재시작 후 전체 실행'이 한 번에 통과해야 한다
7. **한 노트북·스크립트 = 한 목적.** 파일명에 순서 번호를 붙인다(예: `notebooks/1A_build_master.ipynb`, `py/panel/21_rent_to_parquet.py`). 여러 곳에서 쓰는 함수는 `py/`의 모듈로 뺀다.
8. **노출(exposure) 질문을 항상 먼저 한다.** 새 변수마다 묻는다. "이것은 노출의 또 다른 얼굴인가, 노출을 통제한 뒤에도 남는 위험 요인인가?"
9. **테스트 구간은 보지 않는다.** 2025년 이후는 레짐 판단용 월별 추이만 보고, 변수·모형 선택에는 쓰지 않는다.
10. **결정은 사람이 한다.** AI(Claude Code)는 코드·반복 실행·검증·선택지 제시를 맡고, 기준값·데이터 포함 여부·변수·모형·해석·테스트 개봉은 사람이 정한다. 런북의 `[결정]` 표시가 그 지점이다. 규약: `docs/WORKFLOW_사람-AI_역할분담.md`

## 5. 도구와 언어

**전 단계 Python 하나로 한다.** 편집기는 VS Code(Python·Jupyter 확장), 환경은 프로젝트 전용 가상환경 `.venv`.

| 단계 | 도구 | 쓰임 |
|---|---|---|
| 0 | requests, python-dotenv, pandas, duckdb | API 호출, 파일 점검, 조인 매칭률 |
| 1 | pandas, statsmodels, lightgbm, ruptures, matplotlib | 데이터 재구축, 음이항 회귀·HAC, ARIMAX, 예측 비교, 구조변화 |
| 2A | duckdb(SQL), pyarrow, scikit-learn | 약 1억 행 적재·패널, 대여소 군집 |
| 2B | lightgbm, statsmodels, lifelines | 위험 모형, 해석 모형(음이항·Cox) |
| 3 | requests, duckdb, streamlit (필요하면 FastAPI) | 수집기, 대시보드 |

1차 분석의 R 도구와의 대응: tidyverse → pandas, MASS::glm.nb → statsmodels 음이항, sandwich(HAC) → `cov_type="HAC"`, forecast::auto.arima → statsmodels SARIMAX + 차수 격자 탐색, strucchange → ruptures, survival::coxph → lifelines.

### 코드 스니펫에 대해

- 문서 안의 코드는 **뼈대**다. 컬럼 이름은 단계 0에서 확인한 실제 이름으로 바꿔 쓴다.
- 검증 수준: 판다스로 쓴 부분(평가 하네스와 나이브 수치, 날씨 시나리오, 전처리 파생변수, EDA 표, API 호출 함수의 페이지 처리)과 패널의 창 함수 논리는 실제 데이터·샘플 데이터로 실행해 확인했다. statsmodels·lightgbm·DuckDB·실제 API 호출은 작성 환경에 설치·접속할 수 없어 문법 기준으로 썼다. 처음 돌릴 때 작은 표본으로 먼저 확인한다.
- 첫 실행에서 오류가 나면 먼저 컬럼 이름, 날짜 형식, 인코딩을 의심한다.
- 날짜·시간은 모두 한국 시간(KST) 그대로 쓴다. UTC로 바꾸지 않는다.

## 6. 핵심 개념 (용어집)

| 용어 | 뜻 |
|---|---|
| 노출(exposure) | 사건이 일어날 수 있었던 기회의 양. 대여 건수, 이동거리, 이용시간 |
| offset | 계수를 1로 고정한 log(노출) 항. `log(E[y]) = log(노출) + Xβ`가 되어 모형이 '비율(고장률)'을 추정한다 |
| 고장률(신고율) | 신고 건수 ÷ 노출. 예: 대여 만 건당, 1,000km당 |
| 나이브 | 가장 단순한 예측. 주간 합계 기준으로는 "다음 주 = 지난주"가 가장 강했다 |
| MAE% | MAE ÷ 실제값 평균 × 100 |
| skill(개선율) | 1 − MAE(모델) / MAE(나이브). +20%면 나이브보다 오차가 20% 작다. 음수면 나이브보다 못하다 |
| rolling-origin | 예측 시점을 한 칸씩 옮기며 반복 평가. 각 시점은 그 이전 데이터만 쓴다 |
| 예측구간 커버리지 | 80% 구간이 실제로 80%를 덮는지 |
| pinball 손실 | 분위수(예: 10%, 90%) 예측의 정확도 지표 |
| IRR(발생률비) | exp(계수). 1.10이면 고장률 10% 증가 |
| HAC 표준오차 | 자기상관·이분산이 있어도 믿을 수 있는 표준오차(Newey-West) |
| precision@K | 위험 상위 K대 중 실제로 다음 주에 신고된 비율 |
| lift | 상위 K대의 신고율 ÷ 전체 신고율 |
| 헛대여 | 빌리자마자(수 분 이내) 같은 대여소에 반납한 대여. 고장 신호 후보 |
| 레짐 변화 | 데이터가 만들어지는 구조 자체가 바뀜. 예: 2025년 신고 약 30% 감소 |

### 이미 계산해 둔 기준 숫자 (재현되면 파이프라인이 맞다는 뜻)

2024년, '향후 7일 합계' 타깃, 나이브 "다음 주 = 지난주", 원점 360개(2024-01-01 ~ 12-25).

| 부품 | 주간 평균 | 나이브 MAE | 나이브 MAE% | 1차 LSTM MAE% | 1차 GRU MAE% |
|---|---|---|---|---|---|
| 타이어 | 568.0 | 100.9 | 17.8% | 17.0% | 14.0% |
| 체인 | 728.4 | 139.0 | 19.1% | 18.0% | 18.9% |
| 안장 | 471.6 | 95.4 | 20.2% | 22.9% | 15.1% |
| 페달 | 381.6 | 75.6 | 19.8% | 18.8% | 22.5% |

1차 모델 중 어느 것도 네 부품 모두에서 나이브를 이기지 못했다. 재수행의 목표는 **"고정된 나이브 세트를 모든 부품에서 꾸준히 이기는 것"**이다.

## 7. 이미 확인된 사실 (2026-09-27 조사, 단계 0에서 재확인)

| 항목 | 값 |
|---|---|

## 10. 이 런북을 쓰는 법 (Claude Code와 함께)

1. 세션 시작: `git pull` → `claude` → `/next`. Claude가 `docs/STATUS.md`와 해당 런북 절을 읽고 계획을 제시한다. 승인하면 실행한다.
2. 절차의 체크박스(`- [ ]`)는 결과를 확인한 뒤 체크한다. 런북과 다른 결과가 나오면 해당 절에 "결과(날짜)" 메모를 남긴다.
3. `[결정]`과 **체크포인트**에서는 `/checkpoint 주제`로 근거와 선택지를 받고, 사람이 고른 뒤 `/decide 결정 내용`으로 결정 로그에 남긴다.
4. 절차가 끝나면 `/quiz`로 이해를 확인한다. 막힌 질문은 `docs/interview_notes.md`에 쌓인다.
5. 세션 끝: `/wrapup` → 커밋 승인 → `git push`.
6. 계획대로 안 가는 것은 실패가 아니다. 어디서 왜 안 갔는지 기록하면 보고서의 '시행착오' 절이 된다.
