## 3B-1. 화면 ① 정비·부품 예측

> **결과(2026-10-08)**: `app/pages/1_정비_부품_예측.py`. 예측 스냅샷이 비어 있는 동안은 안내문(일별 자료 35일 뒤 산출).

### 구성 (위에서 아래로)

1. **기준 시각 띠:** "대여 데이터 ○월 ○일 ○시까지 / 고장신고 ○월 ○일까지 / 예측 발행 ○월 ○일"
2. **요약 카드 5개:** 타이어·체인·안장·페달·전체의 다음 7일 예측 건수와 80% 구간, 지난주 실제와의 차이
3. **추이 그림:** 부품별 주간 실제(점) + 과거 예측(선) + 다음 주 예측 구간(띠)
4. **준비 수량 표**

   | 부품 | 예측 | 80% 구간 | 권장 확보 수량(구간 상단) | 지난주 실제 |
   |---|---|---|---|---|

   '권장 확보 수량 = 80% 구간 상단'이면 결품 가능성이 약 10%라는 뜻이다. 표 아래에 이 문장을 적는다.
5. **인력 계산기:** 입력값을 사용자가 바꿀 수 있게 한다.
   - 대당 평균 수리 시간(분): 기본 30 (현장 보도: 한 대 10분 ~ 1시간 이상)
   - 정비원 1명의 주당 수리 가능 시간: 기본 30시간
   - 필요 인원 = Σ(예측 건수 × 수리 시간) ÷ 60 ÷ 1인 주당 시간
   - "신고 건수 기준이라 실제 수거(신고의 약 2배)보다 작게 나온다"를 함께 표시
6. **예측을 믿어도 되나:** 최근 8주 부품별 MAE%와 나이브 대비 개선율
7. **(단계 2 완료 후) 자치구별 분해:** 자치구별 예측 막대 또는 지도

### 확인
- [ ] 관리자가 30초 안에 "다음 주 타이어 몇 개"를 읽을 수 있다
- [ ] 구간(불확실성)이 숫자와 함께 보인다
- [ ] 정확도 추적이 있다(신뢰의 근거)

## 3B-3. 화면 ③ 자전거 조회 (시민)

> **결과(2026-10-08)**: `app/pages/3_자전거_조회.py`. 집계값만. 번호 재부여 자전거는 '도입 후 경과: 확인 불가'.

### 보여주는 것 — 모두 **집계값**

| 항목 | 예시 | 원천 |
|---|---|---|
| 점검 필요 가능성 등급 | 주의 | `bike_risk_latest.grade` |
| 이유(최대 3개) | 마지막 신고 이후 주행거리가 깁니다 | `reasons` |
| 최근 30일 이용 횟수·주행거리 | 42회 · 97km | `bike_card` |
| 마지막 신고 이후 주행거리 | 310km | `bike_card` |
| 최근 90일 신고 이력 | 9/03 타이어, 8/11 체인 (날짜·유형만) | `bike_card` |
| 도입 후 경과 | 약 4년 | `bike_card` |
| 기준 시각 | 9/28 07:00 갱신 | `data_status` |

### 보여주지 않는 것

- **개별 대여 기록(시각, 대여·반납 대여소)** — 공개 원자료에 있더라도, 번호 하나로 바로 조회되면 "그 시간에 그 자전거를 탄 사람"의 동선을 추적하는 데 쓰일 수 있다
- 이용자 속성(생년·성별)
- 마지막 반납 위치(시민 화면에서는 필요 없다. 공단 화면 ②에만)
- 절대 확률("고장 확률 37%") — 신고 누락이 많은 라벨로 만든 값이라 오해를 부른다

### `bike_card` 만들기 (07의 운영 DB에서 매일)

```sql
CREATE OR REPLACE TABLE bike_card AS
WITH t AS (
  SELECT bike_id,
         count(*) FILTER (WHERE rent_dt >= now() - INTERVAL 30 DAY)                 AS trips_30d,
         sum(use_m) FILTER (WHERE rent_dt >= now() - INTERVAL 30 DAY) / 1000.0      AS km_30d
  FROM trips_live GROUP BY bike_id
), f AS (
  SELECT bike_id,
         string_agg(strftime(reg_date, '%m/%d') || ' ' || kind, ', ' ORDER BY reg_date DESC) AS reports_90d
  FROM fail_live WHERE reg_date >= current_date - INTERVAL 90 DAY GROUP BY bike_id
)
SELECT b.bike_id, t.trips_30d, t.km_30d, f.reports_90d,
       p.km_since_rep, round(p.age_days / 365.0, 1) AS age_years
FROM bike_info b
LEFT JOIN t USING (bike_id)
LEFT JOIN f USING (bike_id)
LEFT JOIN panel_latest p USING (bike_id);
```

`fail_live`는 07의 `raw_fail`을 표준 이름(`bike_id`, `reg_date`, `kind`)으로 바꾼 뷰, `panel_latest`는 가장 최근 완결 주의 패널 행이다.

### 문구 지침

| 상황 | 쓰는 말 | 쓰지 않는 말 |
|---|---|---|
| 등급 이름 | 점검 권장 / 주의 / 보통 / 낮음 | 위험 / 안전 / 고장 |
| 등급 설명 | "비슷한 따릉이보다 신고될 가능성이 높은 편입니다" | "곧 고장 납니다" |
| 데이터 설명 | "이용자 고장신고 기록 기준" | "고장 기록" |
| 행동 안내 | "타기 전에 브레이크와 타이어를 확인하고, 이상하면 따릉이 앱으로 신고해 주세요" | "타지 마세요" |
| 기록 없음 | "최근 90일 이용 기록이 없는 번호입니다. 번호를 다시 확인해 주세요" | 빈 화면 |

색만으로 등급을 구분하지 않는다. 글자와 아이콘을 같이 쓴다(색각 이상 사용자 배려).

### 고지 문구 (화면 하단 고정)

> 이 서비스는 서울시 공공데이터로 만든 **비공식 참고 정보**입니다. 서울특별시·서울시설공단의 공식 서비스가 아니며, 자전거의 안전을 보증하지 않습니다. 등급은 이용자 고장신고 기록을 바탕으로 한 통계적 추정이며, 신고되지 않은 고장은 반영되지 않습니다. 이상이 있으면 따릉이 앱으로 신고해 주세요.

### 출처 표시 (공공누리 제1유형 권장 형식에 맞춰 채운다)

> 본 서비스는 '(데이터셋 페이지에 적힌 제공기관)'에서 '(연도)' 작성하여 공공누리 제1유형으로 개방한 '서울특별시 공공자전거 대여이력 정보', '서울특별시 공공자전거 고장신고 내역'을 이용하였으며, 해당 저작물은 '서울 열린데이터광장, https://data.seoul.go.kr'에서 무료로 내려받을 수 있습니다.

- 공공기관이 후원하거나 특수한 관계인 것처럼 보이는 표현·로고를 쓰지 않는다(공공누리 금지 사항)
- 에어코리아 자료(3유형, 변경 금지)는 화면에 가공해서 보여주지 않는다

## 3B-4. 구현 (Streamlit)

> **결과(2026-10-08)**: Streamlit 1.65. `app/lib.py`가 스냅샷을 10분 캐시로 읽고 48시간 넘으면 경고. AppTest로 4화면 예외 0(2026-10-08).

```
app/
├─ Home.py                    소개, 기준 시각, 고지·출처
├─ pages/
│  ├─ 1_정비_부품_예측.py
│  ├─ 2_점검_우선순위.py
│  └─ 3_자전거_조회.py
└─ lib.py                     스냅샷 읽기(캐시), 공통 문구
```

```python
# app/lib.py
import pandas as pd, streamlit as st

@st.cache_data(ttl=600)                         # 10분마다 새 스냅샷 확인
def load(name):
    return pd.read_parquet(f"serving/{name}.parquet")

DISCLAIMER = "서울시 공공데이터로 만든 비공식 참고 정보입니다. 서울특별시·서울시설공단의 공식 서비스가 아닙니다."
```

```python
# app/pages/3_자전거_조회.py
import re, pandas as pd, streamlit as st
from lib import load, DISCLAIMER

num = lambda v: 0 if pd.isna(v) else v             # 결측(NaN)을 0으로
txt = lambda v: "없음" if pd.isna(v) or v == "" else v

st.title("따릉이 자전거 상태 조회")
st.caption(DISCLAIMER)
q = st.text_input("자전거 번호", placeholder="예: SPB-12345 또는 12345")

if q:
    m = re.search(r"\d+", q)
    if not m:
        st.warning("번호의 숫자 부분을 입력해 주세요.")
    else:
        bid = int(m.group())
        risk, card = load("bike_risk_latest"), load("bike_card")
        r, c = risk[risk.bike_id == bid], card[card.bike_id == bid]
        if c.empty:
            st.info("최근 90일 이용 기록이 없는 번호입니다. 번호를 다시 확인해 주세요.")
        else:
            c = c.iloc[0]
            if not r.empty:
                st.subheader(f"점검 필요 가능성: {r.grade.iloc[0]}")
                for reason in r.reasons.iloc[0]:
                    st.write(f"· {reason}")
            col1, col2, col3 = st.columns(3)
            col1.metric("최근 30일 이용", f"{int(num(c.trips_30d))}회")
            col2.metric("최근 30일 주행", f"{num(c.km_30d):.0f}km")
            col3.metric("마지막 신고 이후 주행", f"{num(c.km_since_rep):.0f}km")
            st.write(f"최근 90일 신고: {txt(c.reports_90d)}")
            st.caption("타기 전에 브레이크와 타이어를 확인하고, 이상하면 따릉이 앱으로 신고해 주세요.")
```

- 화면 ①의 추이 그림은 `altair`로 선 + 구간 띠를 겹친다. 화면 ②의 지도는 `st.map`(열 이름 `lat`, `lon`) 또는 `pydeck`
- 한 번에 한 대씩만 조회되게 한다(번호 목록을 통째로 내려받는 기능 없음). 무작위 대량 조회를 어렵게 한다
- 휴대폰 화면에서 먼저 확인한다. 시민은 대여소 앞에서 폰으로 본다

## 3B-6. 사용성 테스트 (1~2일)

## 3B-7. 선행 서비스(RIDEY)와의 관계

- RIDEY는 5분마다 '연속 헛대여'로 지금 고장일 가능성을 알리고, 자전거번호 조회를 제공한다(2026-09-25부터 실시간 경보)
- 이 프로젝트의 차별점은 세 가지다
  1. 누적 마모·지형·날씨 노출 기반 **부품별 위험**(06)
  2. 정비센터용 **부품·인력 수요 예측**(04)
  3. 헛대여 신호를 서울 고장신고로 **검증한 결과**(06 2B-5)
- 제안서와 화면 소개에 선행 서비스를 밝히고 차이를 설명한다. 필요하면 협업(서로의 신호 공유)을 제안하는 것도 방법이다

---

## 흔한 함정

- **시민 화면에 개별 대여 기록을 보여준다** → 동선 추적 위험. 집계만
- **'안전' 등급** → 신고 누락 데이터로 안전을 보증할 수 없다
- **기준 시각이 없다** → 반기 파일에 의존하는 정보가 몇 달 전 것일 수 있다. 항상 표시
- **대시보드가 느리다** → 스냅샷을 작게(최근 것만), `st.cache_data`
- **색에만 의존** → 글자·아이콘 병행

## 완료 기준

- [ ] 세 화면이 스냅샷만으로 동작하고, 휴대폰에서 읽힌다
- [ ] 고지·출처 문구가 모든 화면에 있다
- [ ] 사용성 테스트 결과와 수정 내역
- [ ] 배포 주소와 2분 데모 영상(09 제안서에 넣는다)
