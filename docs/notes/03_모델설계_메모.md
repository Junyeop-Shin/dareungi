# 모델 설계 메모

> 어떤 모형을 어떻게 짰고 왜 그렇게 정했는지를 적는다.
> 실행 코드: 단계 1B·1C 노트북 (아직 시작 전) · 절차: `docs/runbook/03`, `04`
> 마지막 갱신: 2026-10-05

## 이미 정해진 것

| 무엇을 | 어떻게 | 왜 |
|---|---|---|
| 맞히려는 값 | **신고 건수**(신고율이 아니다). 전체는 신고 건수(`total_faults`), 부품별은 행 수(`fail_tire` 등). 신고율은 건수를 맞히기 위한 중간 단계: 건수 = 대여량 × 신고율 | 한 행이 신고×유형이라 신고 건수는 행 합계보다 약 13% 적다. 전체는 실제 신고 건수로, 부품별은 유형이 붙은 행으로 센다 |
| 대여량의 위치 | 설명변수가 아니라 노출(offset)로 넣는다 | 1차 분석은 대여량으로 고장 건수를 회귀해 "많이 타면 많이 고장 난다"만 학습했다. 노출로 내려야 신고율을 설명하는 요인이 보인다 |
| 비교 기준 | 모든 결과표 첫 줄은 나이브("다음 주 = 지난주") | 이걸 못 이기면 모형을 쓸 이유가 없다. 못 이기면 그대로 보고한다 |
| 구간 나누기 | 학습 **2021-04-08** ~ 2023 / 검증 2024 / 테스트 2025 ~ 2026 상반기 (체크포인트 A, 2026-10-05) | 원래 계획은 2020년부터였으나 2020-05 ~ 2021-03은 신고율이 절반인 기간(신고 방식이 달랐던 것으로 판단)이라 뺐다. 1B에서 2022-03 시작과 비교한다. 테스트 구간은 마지막에 한 번만 본다 |
| 수준 적응 변수 | 모든 예측모형에 최근 4주 신고율을 넣는다 | 테스트 구간(2025 ~)은 신고율이 약 20% 낮은 다른 레짐이고 원인을 모른다. 모형이 최근 수준을 스스로 따라가야 한다. 나이브("지난주만큼")는 수준을 자동으로 따라가므로, 이 변수가 없으면 모형이 나이브에 지기 쉽다 |
| 테스트 결과 보고 | 2025 상반기·하반기·2026 상반기로 나눠 보고 | 레짐이 바뀐 직후와 안정된 뒤의 성능을 구분해 보기 위해 |

## 변수 (체크포인트 B, 2026-10-05) — 목록은 `docs/variables_v1.md`

| 무엇을 | 어떻게 | 왜 |
|---|---|---|
| 예측의 구조 | 신고 건수 = 대여량 예측 × 신고율 예측 | 주간 신고 건수 변동의 70 ~ 85%는 대여량이 정한다. 대여량을 알면 오차가 22% → 8%로 준다. 신고율은 최근 수준에 계절·한파만 얹으면 된다 |
| 한파 | `cold_wave`와 `winter_anom` 두 형태를 1B에서 비교해 하나를 고른다 | 더미는 단순하고, 연속값은 추위의 정도를 반영한다. 어느 쪽이 나은지는 데이터로 정한다 |
| 개입·환경 변수 | 설명 모형(1B)에서는 민감도 분석으로만. 유연한 예측 모형(1C)에서는 전부 넣은 것과 뺀 것을 검증 구간에서 비교해 좋은 쪽 채택 | 대부분 날짜만 있고 효과가 확인되지 않았다. 넣어서 좋아지는지를 검증 성능으로 판단한다. 단, 학습 구간에서 값이 바뀌지 않는 변수는 배울 수 없다 |
| 학습에서 빼는 날 | `no_service`(운영 중단), `report_anomaly`(2023-09-07 ~ 10-10 신고 누락) | 신고 누락 기간은 9월의 계절 추정을 10포인트 누른다 |
| EDA에서 뺄 가능성이 높게 나온 것(더위, 얼었다 녹은 날, 평균기온, 징검다리, 눈) | 처음부터 빼지 않고 일단 넣은 뒤, 뺀 모형과 성능을 비교해 남길지 정한다 | EDA는 변수를 하나씩 따로 본 것이라 놓친 효과가 있을 수 있다. EDA의 근거(1.01, 0.99, 눈 25일 등)는 `docs/variables_v1.md` 비고란에 남겨 두고, 최종 판단은 검증 성능으로 한다 |
| 넣지 않는 것 | 누적 대여량, 대여량 이동평균 | 이용량의 다른 모습이라 원칙상 뺀다 |

## 아직 정하지 않은 것

- **노출을 무엇으로 할지**: 대여건수(`rentals`), 이용시간(`use_hours`), 이동거리(`dist_km`) 중에서 1B에서 비교해 정한다.
  - 알고 들어갈 것: 이동거리는 학습 구간 안에서 약 560일이 비어 있다(2020-03 ~ 2021-01-04, 2021-08 ~ 2022-03. 거리가 0으로 기록된 대여가 10% 이상인 날). 대여건수와 이용시간은 빈 날이 없다.
- **2021년 처리**: 2021-02~12는 신고에 시각이 없어 `reports`가 실제보다 약간 적다. 더미 변수를 넣을지, 2022년부터 학습할지 비교한다.
- **운영 중단일**: `no_service`(2019-09-07)는 노출이 0이라 제외한다. `partial_service`(09-06, 09-08)를 뺄지는 학습 구간 밖이라 영향이 없을 것으로 보이지만, 구간을 넓히면 다시 본다.
