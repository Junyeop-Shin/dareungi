## 지금 위치

분석(단계 0 ~ 2)과 파이프라인·대시보드(3A·3B)는 다 만들었고, 맥북에서 예약 실행과 슬랙 경보가 돌고 있다. 서버 배포는 2026-10-10에 했다(AWS Lightsail 서울). 남은 것은 보고서·제안서 마무리, 사용성 테스트다.
마감: SK AX 자기소개서 **2026-10-11(일)**.

## 남은 일 (순서대로)

1. **자기소개서** — 재료: `docs/report_stage1.md`, `docs/notes/04_레짐원인_메모.md`, `docs/notes/06_위험모형_메모.md`
2. **배포** — 2026-10-10에 AWS Lightsail 서울(Ubuntu 24.04 · 4GB, 월 24달러)에 올렸다. 주소는 **https://ttareungi-care.duckdns.org** (DuckDNS, 비밀번호 없이 공개). 순서와 겪은 문제는 `deploy/README.md`. 남은 것: 서버가 정상으로 도는 것을 확인한 뒤 맥북 `crontab -r`, 과금 확인(Billing → Credits). 안 쓸 때는 인스턴스와 고정 IP를 삭제해야 과금이 멈춘다
3. **보고서 요약·다듬기** — `docs/report_stage1.md`(초안). 쓸 때 옆에 펴 놓고 볼 정리 문서: `docs/project_guide.html`(브라우저로 연다. 보고서 목차 순서로 프로젝트 전체를 정리했고, 숫자마다 출처 표를 붙였다. 18절에 문서와 표가 달랐던 곳의 목록이 있어 옛 문서의 문장을 그대로 옮기면 안 되는 곳을 알 수 있다). 단계 2·레짐 원인 결과는 3절·부록에 일부만 들어가 있다. 2026-10-09 ~ 10에 생긴 재료: 유형 7칸 예측과 구간 적중(`forecast_track`), 도입 효과 시나리오(`output/tables/impact_scenario.csv`), 운영 감시와 재학습 기준(`docs/pipeline.md`)
4. **서울시 제안(3C)** — `docs/proposal/proposal_draft.md`. 제안 대상·시점, 외부 보도 숫자 재확인, 2분 데모 영상, 정보공개청구(`docs/reference/10` 4절)
5. **사용성 테스트(3B-6)** — 관리자 역할 2 ~ 3명(시민 조회 앱을 없애 시민 역할은 뺀다. 런북 08의 계획은 고치지 않았다). 결과는 `docs/usability_test.md`
6. **2028년 공휴일** — 2027년은 받아 둠(`py/build/holidays.py 2027`). 2027년 여름 이후 `py/build/holidays.py 2028`
7. **다음 위험 모형 판(v2)** — 지금 모형은 테스트를 연 뒤라 그대로 두고, 다시 만들 때 바꿀 것(`docs/notes/07`):
   - 기준(offset)을 다음 주 주행 km 대신 **다음 주 대여 수**로. 신고는 km보다 대여 횟수에 비례한다(R11)
   - '수리 추정' 변수(last_repaired, 신고 뒤 48시간 넘게 대여 없음)를 **신고 뒤 첫 대여가 다른 대여소에서 시작했나**로. 48시간 기준은 수거 여부를 잘 못 가린다(R13)
   - 처음부터 **다음 주 신고 확률**을 목표로 맞추고 확률 보정을 최근 주로 다시 맞추는 방식(R19·R20)
   - **정답 주가 테스트 구간에 걸치는 검증 주는 뺀다.** 지금 판은 검증 마지막 주(2025-12-29 주)의 정답(다음 주 신고)이 테스트 구간(2026-01-05 ~ 11)에서 온다(코드 검토 5번, 결정 로그 2026-10-10)
   - 새 판은 테스트 구간이 없으므로 2026-07 이후 자료와 운영 주로 평가한다

## 열린 결정

- 메뉴 줄에 넣을 서비스 이름(정하면 홈 제목을 '한눈에 보기'로 바꾼다)
- 위험 모형 재학습 기준: 채점이 8주 쌓이는 2026-12 초에 처음 8주 평균을 보고 확정(2.7배 이상이면 2.5배 기준 그대로)
- 전체 신고를 '신고 건수' 대신 '신고된 자전거 수'로 셀지(보류. 바꾸면 신고율·예측 구간·검증을 다시 계산)

- **운영 원자료 보존 기간**: 두 번째 반기 대사(2027-07)까지 `raw_rent`를 지우지 않고, 그때 얼마나 남길지 정한다(사람, 2026-10-10). 100일에 약 5GB씩 늘어 2027-07에 약 19GB. 서버 디스크가 50GB보다 작으면 첫 대사(2027-01) 뒤로 앞당긴다
- 주간 예측 예보판·달력판: 2026-10-12부터 12주 운영 성적이 차면(2027-01 초) 교체 조건을 확인한다(`fc_compare`, 결정 로그 2026-10-08)
- 정비 구역 구분: 센터별 실제 담당을 몰라 한강 기준(강북 14구·강남 11구)으로 나눠 두었다 → `app/common/seoul_tiles.py`의 `SECTORS`
- `han_river` 대여소 지도 검수(여가 통행 구분에 쓰임)
