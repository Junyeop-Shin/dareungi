# 확장 프로젝트 설계 쟁점 7개 — 답변 및 문헌 정리

작성: 2026-09-13

## 1. 수리 후 내구성 — "수리된 자전거 = 새 자전거"인가
**가정하지 말고 추정할 것.** Kijima 가상나이(virtual age) 모형 / generalized renewal process가 표준 해법.
- `q=0` 완전수리(as-good-as-new), `q=1` 최소수리(as-bad-as-old), 0<q<1 그 사이. **q를 데이터에서 추정 → 답이 곧 결과**
- 부품별 q 차이 가설: 타이어·체인은 교체되므로 q≈0, 프레임 정렬·베어링은 q≈1

우리 데이터에는 '수리'가 없고 '신고'만 있으므로 3단계 접근:
1. **(시작점)** Andersen-Gill 재발사건 — 수리 완전성 가정 안 함. + **PWP gap-time**으로 회차별 기저위험 분리 → "2차 고장 이후 위험이 1차와 다른가" 직접 검정 = 수리효과 간접 추정
2. **(독창적 지점)** 신고 후 대여이력 공백(gap)을 수리 대리변수로. gap 길다=수거·정비됨 / gap≈0=신고만 되고 계속 운행. 이 이분법으로 자연실험에 가까운 비교. 정비 인력 배분이라는 원래 목표와 직결
3. (여유 시) Kijima ARA1로 q 명시적 추정

바르셀로나는 정비기록이 있어 MO unit을 직접 정의(암묵적 완전수리 가정)하고, 한계로 "정비기록은 교체 시점이지 고장 시점이 아니다"를 인정. **우리는 반대(고장 시점은 알고 수리는 모름) → 차별점으로 서술 가능**

## 2. 왕복 대여(같은 대여소 반납) 활용
**쓸 수 있고 오히려 더 좋은 관측.** 이동거리로 노출(분모)은 정확히 측정됨. 순 고도차가 0인 게 단점이 아니라, **등판·내리막이 정확히 상쇄된 주행임을 안다**는 장점.
- 식별 전략: 같은 거리·기상에서 **왕복 vs 편도 상승 주행**의 고장률 차이 = 순 등판 효과 (준실험)
- 처리: 왕복 더미 + 왕복거리/편도거리 노출 분리 (`offset(log(총거리))` + 왕복거리비율 공변량)
- Phase 0에서 왕복 비율 먼저 집계할 것 (한강변 대여소에서 높을 것)
- 선행: 대한교통학회 「따릉이 이용 유형별 특성 분석: 이동형과 루프형」, 서울대 「Round-trip Data from Ddareungi」

## 3. 대여소 속성 기반 통행목적 분류
방향은 맞음 — 목적은 주행강도(속도·정지출발·노면)와 직결되며 **고도차로는 안 잡히는 독립 차원**. 바르셀로나에도 없는 차원.

**단, 토지이용 사전 라벨링은 비권장** (조인 작업량 크고 실제 목적과 느슨, 같은 대여소도 아침=출퇴근/주말=여가).

**대안: 대여소별 요일×시간대 대여/반납 프로파일(168차원) 군집화**
- 출근시간 반납 초과=업무지구 / 대여 초과=주거지 / 주말 낮 왕복 집중=여가 / 지하철 인접+단거리=환승접근
- 통행 목적은 대여소가 아니라 **통행 단위**로 정의 (대여소쌍 + 시간대 + 요일 + 왕복여부)

**가설 방향 재고 권고:** "여가가 더 영향"보다 **"목적별로 마모되는 부품이 다르다"**로 세울 것
- 여가 → 거리 기반 마모(타이어·체인)
- 출퇴근 → 급가속·급제동, 도심 노면, 정지-출발 반복 → 충격·토크 기반 마모(브레이크·페달)
- 결과가 어느 쪽이든 논문이 되고 실무적으로 유용
- 반드시 `offset(log(거리))` 하에서 목적별 계수를 볼 것

## 4. 바르셀로나 논문 (Grau-Escolano, Bassolas & Vicens 2024, EPJ Data Science 13:46, arXiv:2404.17217)

**데이터**: 이용 2019.04~2022.12 5,300만 건(기계식 62%/전기 38%), 정비 2020.09~2023.01 31만 건(12카테고리 87세부), 통행 필터 2~60분

**MO unit**: 같은 자전거·같은 부품의 연속된 두 수리 사이 기간. 각 unit을 독립 개체로. **좌측검열(첫 unit) 제거 / 우측검열 유지**

**부품 3종**: 브레이크 패드, 바퀴살, 체인 (데이터 비중 기준 선정)

**거리·고도 추정 — 가장 실용적으로 중요**
- 거리: **OpenRouteService API** (OSM 기반 자전거 추천 경로). 직선거리 아님
- 고도: **OpenTopoData API**로 대여소 고도 → **출발-도착 고도차만** 사용 ("simplified"로 한계 인정)
- 속도 = 거리 ÷ 소요시간
- → 우리 프록시 설계의 직접적 선례. 두 API 모두 무료

**공변량**: 일평균 기온, 평균 기압(강수량은 최종 제외!), 누적 일일 거리, 평균 속도, 전기/기계 이진, 타 부품 수리 횟수

**모형**: Cox PH / MTLR / Conditional Survival Forest / **DeepSurv** → DeepSurv 최고 (RMSE 25~33% 개선, MAPE<33%, R²>0.92). MTLR > CPH

**SHAP**: ① 누적 거리 ② 자전거 모델 ③ 평균 속도 → **"누적 거리 1위"가 offset/시간축 설계의 정당화**

**한계(=우리 기회)**: GPS 부재, **고도 단순화**, 검열 불균형, 정비기록은 교체 시점이지 고장 시점 아님

**차용**: MO unit → 신고 간 간격, 검열 처리 규칙, ORS+OpenTopoData 파이프라인, 2~60분 필터, 모형 사다리, SHAP
**차별화**: ① 지형 정면 취급(그들의 명시적 한계를 메움) ② 통행 목적 차원 ③ 신고-공백 분석 ④ 단일 기종 코호트(기종 교란 없음)

## 6. 기존 분석 보완 + 신규 데이터
**신규 데이터는 반드시 추가. 기존 보완은 3가지만.**

분기별 만건당 고장률: 2022Q1~Q4 40.9/40.6/47.6/45.9 → 2023 40.3/37.8/37.1/39.8 → 2024 31.8/37.7/38.8/37.2
→ **2023년부터 37~40에서 안정.** 동질 레짐이 현재 2년뿐. 2025+2026상반기 추가 시 **2년 → 3.5년** (연 계절성 2회 → 3~4회 관측). 대여이력·고장신고 모두 2026년까지 공개됨.

**전면 보완은 비권장** — 지적사항 대부분(카운트에 OLS, 노출 미통제, SARIMA m=365)이 확장 설계에서 자동 소멸.

**딱 3가지 (2~3일)**:
1. 표 3·표 4 오류 정정 + 데이터 버전 고정 (반나절)
2. HAC 표준오차로 회귀 재해석 (반나절) → **확장 프로젝트의 동기 문단**이 됨
3. 2026년 상반기까지 데이터 확장 + 집계 재생성 (1~2일) — 어차피 필요한 작업
+ 나이브 벤치마크 표 (5분)

나머지(SARIMAX, rolling-origin, LSTM 재튜닝)는 시간 남으면.

## 7. 모델 추천

**가장 중요한 결정: 시간축을 누적 주행거리로.** "투입 300일째"가 아니라 "1,200km 주행 시점"의 위험. 노출 문제 근본 해결 + 바르셀로나 SHAP 1위와 정합. 거리 품질 나쁘면 누적 대여 횟수로 대체.

| 단계 | 모형 | 도구 | 비고 |
|---|---|---|---|
| 0 | 자전거×월 패널 기술통계 | DuckDB | 만km당 고장률 개체간 분포 자체가 결과 |
| 1 | **음이항 GLM + offset(log 주행거리)** | `MASS::glm.nb` | 기준선. **여기까지만 해도 프로젝트 성립** |
| 2 | 음이항 혼합효과(자전거 random effect) | `glmmTMB` | 개체 체질 분리, frailty 대응 |
| 3 | **Cox PH + Andersen-Gill** (`cluster(bike_id)`) | `survival::coxph` | 주력. 바르셀로나와 직접 비교. **학회 발표 수준** |
| 3b | **PWP gap-time** | `survival` | **쟁점 1의 답을 직접 제공** |
| 4 | **DeepSurv** / Conditional Survival Forest | `pycox`, `scikit-survival` | 비선형·상호작용 |
| 5 | SHAP | `shap` | 바르셀로나와 동일 형식 비교 |

**부품별**: 개별 모형 5개 권장(해석 명확). 경쟁위험(Fine-Gray)은 한 부품 고장이 타 부품 관측을 실제로 막을 때만 — 따릉이는 신고 후에도 운행되는 경우가 있어 가정 확인 필요.

**금지**: ① 개체 단위로 간 뒤 다시 일별 총량 ARIMA/LSTM ② RF/XGBoost 이진분류(검열 무시 + 노출 암묵 → 또 "많이 탄 자전거가 고장") ③ 테스트셋으로 모델 선택

**검증**: 시간 기반 분할(앞=학습/중간=검증/뒤=테스트, 테스트는 마지막 한 번). 지표 C-index + Brier score(+ 바르셀로나 비교용 RMSE/MAPE). 나이브 벤치마크 필수 — 누적거리 단일변수 모형, 부품별 평균수명 상수 모형.

## 권장 진행 순서
- **1주차**: 기존 분석 정리 3가지 + **Phase 0 조인 검증**(고장신고 자전거번호의 대여이력 매칭률) — 여기서 안 되면 계획 재검토
- **2주차**: 2026상반기까지 데이터 수집. 대여소 좌표 + OpenTopoData 고도 + OpenRouteService 거리 룩업. 왕복 비율·대여소 시간대 프로파일 군집
- **3~4주차**: 자전거×월 패널 구축 (DuckDB) — 작업량 대부분
- **5주차**: 음이항 GLM으로 핵심 결과 — **최소 완성 지점**
- 이후: Cox/AG → PWP → DeepSurv
