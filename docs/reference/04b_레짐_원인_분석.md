## R1. 부품별 변화점 (반나절, 새 데이터 불필요)

입력: `data/processed/daily_master_v2.parquet`

1. 주 단위로 부품별 신고율(대여 만 건당)을 만든다
2. 계절을 지우기 위해 **전년 같은 주 대비 비율**(`log(rate_w) − log(rate_{w−52})`)을 만든다. 수준이 영구적으로 바뀌면 이 값은 변화 시점에 계단처럼 내려가고, **정확히 52주 뒤에 0으로 돌아온다**. 이 '내려갔다 1년 뒤 복귀'가 수준 이동의 서명이다
3. 창(2020-07 ~ 2022-06, 2024-01 ~ 2026-06)마다 부품별로 `ruptures`(Binseg, 비용 `l2`)로 변화점을 찾는다. **전년 동주비에는 계단이 두 개 있다**(2025-03 하강 + 2026-03 복귀. 2020-07 창도 2020-05 하락의 복귀가 2021-05에 겹친다). 그래서 `n_bkps=1`이 아니라 `n_bkps=2`로 찾거나, 변화점은 계절을 뺀 수준 시계열(예: 로그 신고율의 STL 잔차)에서 찾고 전년 동주비는 '영구 이동 확인' 그림으로만 쓴다. 방법이 맞는지는 원인을 아는 2018-06-20(앱 개편) 급등을 잡아내는지로 먼저 확인한다
4. 변화점 전후 12주 평균 신고율의 비와 부트스트랩 95% 구간(주 단위 블록)

```python
# py/rc_1_changepoint.py (뼈대)
import numpy as np, pandas as pd, ruptures as rpt
m = pd.read_parquet("data/processed/daily_master_v2.parquet")
parts = ["fail_tire", "fail_chain", "fail_saddle", "fail_pedal"]   # 실제 열 이름으로 바꾼다
w = m.set_index("date")[["rentals"] + parts].resample("W-MON", label="left", closed="left").sum()
rate = w[parts].div(w["rentals"], axis=0) * 1e4
yoy = np.log(rate) - np.log(rate.shift(52))
for lo, hi in [("2020-07-01", "2022-06-30"), ("2024-01-01", "2026-06-30")]:
    for p in parts:
        s = yoy.loc[lo:hi, p].dropna().to_numpy()
        bk = rpt.Binseg(model="l2").fit(s).predict(n_bkps=2)[0]   # 첫 변화점(하강). 두 번째는 52주 뒤 복귀
        print(lo, p, yoy.loc[lo:hi, p].dropna().index[bk])
```

표 `rc_1_changepoints.csv`: 창, 부품, 변화 주, 전후 비, 95% 구간

확인
- [ ] 네 부품의 변화 주가 **같은 주(±1주)**인가, 흩어져 있는가
- [ ] 체인만 크기가 다르거나 서서히 내려가는가(H1)
- [ ] 2025 창에서 전년 동주비가 2026-03 전후로 0 근처로 돌아오는가(영구 이동 확인)
- [ ] 그림 `rc_1_yoy.png`: 부품별 전년 동주비, 변화점에 세로선

## R2. 중복 신고 분해 (반나절, 새 데이터 불필요)

입력: `data/processed/fail_std.parquet` (`bike`, `reg_ts`, `kind`, `keep`)

신고 감소를 조각으로 나눈다. **단위를 정확히 쓴다(2026-10-07 검토에서 고침)**: `fail_std`의 `keep`은 '신고 단위'가 아니라 **행(자전거×유형) 단위**의 48시간 중복 표시다(`docs/notes/01_데이터전처리_메모.md`, 전체의 3.1%). 신고 한 건 = 고유 (자전거, 등록일시)이고, 마스터에는 이미 `total_rows`(행), `reports`(신고 건수), `faild_*`(48시간 중복을 뺀 행)가 있다.

```
log(신고 행) = log(신고된 서로 다른 자전거) + log(자전거당 신고 = reports/bikes) + log(신고당 행 = rows/reports)
48시간 중복 비율(1 − faild/fail)은 네 번째 지표로 따로 본다
```

- 신고된 자전거 수만 줄었다 → 고장이 난 자전거가 줄었거나, 신고하는 사람이 줄었다
- 자전거당 신고 또는 48시간 중복 비율이 줄었다 → **중복 신고 감소**(H5)
- 신고당 행만 줄었다 → 한 신고에 여러 유형을 고르는 방식이 바뀌었다(H7)

```python
# py/rc_2_duplicates.py (뼈대)
import numpy as np, pandas as pd
f = pd.read_parquet("data/processed/fail_std.parquet").sort_values(["bike", "reg_ts"])
f["d"] = f["reg_ts"].dt.normalize()
rep = f.drop_duplicates(["bike", "reg_ts"]).copy()         # 신고 단위 = 고유 (자전거, 등록일시)
gap_d = rep.groupby("bike")["d"].diff().dt.days
rep["repeat3"] = gap_d.le(3)                               # 같은 자전거, 직전 신고 3일 이내
rep["wk"] = rep["d"].dt.to_period("W-SUN").dt.start_time
f["wk"]   = f["d"].dt.to_period("W-SUN").dt.start_time
wk = pd.DataFrame({
    "rows":    f.groupby("wk").size(),
    "rows_dedup": f[f["keep"]].groupby("wk").size(),       # 48시간 중복을 뺀 행
    "reports": rep.groupby("wk").size(),
    "bikes":   rep.groupby("wk")["bike"].nunique(),
    "repeat3": rep.groupby("wk")["repeat3"].mean(),
})
wk["rep_per_bike"] = wk["reports"] / wk["bikes"]
wk["rows_per_rep"] = wk["rows"] / wk["reports"]
wk["dup48"] = 1 - wk["rows_dedup"] / wk["rows"]
```

**2021년의 한계**: 2021-02 ~ 12는 등록일시에 시각이 없어, 같은 자전거의 같은 날 신고 여러 건이 **한 건으로 합쳐진다**(`reports` 과소). 2021-04 비교에서 '자전거당 신고' 조각은 날짜 단위 근사라서 믿을 수 없고, '신고된 자전거 수'와 '신고당 행'만 해석한다. 2025-03 비교는 시각이 있어 문제없다.

표 `rc_2_decomp.csv`: P0, P1 평균과 각 조각의 로그 변화, 감소분 중 각 조각이 차지하는 비율

확인
- [ ] 세 조각의 합이 전체 로그 변화와 같은가(검산)

**지름길(2026-10-07 검토)**: 전 기간 130개월을 pandas로 훑는 `py/rent_history_daily.py`가 이미 있다(52GB, 몇 분). 거기에 열 몇 개(같은 대여소 반납 & 이용시간 ≤2·3·5분, 거리 0)만 더하면 아래 duckdb 루프와 2A 적재를 **기다리지 않고** R4a를 먼저 할 수 있다. 상세 적재(R3 본문)는 R4b 이후에만 필요하다. 아래 duckdb 판은 2A 루프에 합칠 때 쓴다.

```python
def day_signal(csv_path, c):
    con.execute(f"""
    INSERT INTO day_signal
    SELECT CAST(rent_dt AS DATE) AS d, count(*) AS n_trips,
      sum(CASE WHEN same AND use_min <= 2 THEN 1 ELSE 0 END)                 AS sham2,
      sum(CASE WHEN same AND use_min <= 3 THEN 1 ELSE 0 END)                 AS sham3,
      sum(CASE WHEN same AND use_min <= 5 THEN 1 ELSE 0 END)                 AS sham5,
      sum(CASE WHEN same AND use_min <= 3 AND use_m <= 300 THEN 1 ELSE 0 END) AS sham3d,
      sum(CASE WHEN use_m = 0 THEN 1 ELSE 0 END)                             AS dist0
    FROM (
      SELECT try_strptime("{c['rent_dt']}", {FMT}) AS rent_dt,
             TRY_CAST("{c['rent_st']}" AS INTEGER) = TRY_CAST("{c['rtn_st']}" AS INTEGER) AS same,
             TRY_CAST("{c['use_min']}" AS DOUBLE) AS use_min,
             TRY_CAST("{c['use_m']}" AS DOUBLE)   AS use_m
      FROM read_csv('{csv_path}', header = true, all_varchar = true)
    ) WHERE rent_dt IS NOT NULL
    GROUP BY 1
    """)
# 처음 한 번: CREATE TABLE day_signal (d DATE, n_trips BIGINT, sham2 BIGINT, sham3 BIGINT, sham5 BIGINT, sham3d BIGINT, dist0 BIGINT)
```

- 월 경계에서 같은 날짜가 두 파일에 나뉠 수 있다. 저장할 때 `GROUP BY d`로 다시 합친다 → `data/processed/day_signal.parquet`

## R4. 헛대여 대비 신고 — 핵심 판별 (1일)

### R4a. 헛대여율 vs 신고율 (전 기간, `day_signal`)

월별로 헛대여율(대여 천 건당 `sham3`)과 신고율(대여 만 건당)을 같이 그리고, 둘 다 **전년 동월비**로도 그린다.

| 결과 | 해석 |
|---|---|
| 신고율 전년비 ≈ 0.80(체인 0.62 ~ 타이어 0.86), 헛대여율 전년비 ≈ 1.0 | **고장 신호는 그대로, 신고만 줄었다** |
| 둘 다 비슷하게 감소 | 실제 고장 감소(또는 대여 단말·반납 방식 변화로 헛대여 정의 자체가 흔들림 → R4b로 확인) |
| 2021-04에 신고율만 급등 | 신고 체계 변화 |

### R4b. 헛대여 뒤 신고 확률 = 신고 성향 (상세 두 기간)

헛대여가 일어난 자전거가 **24시간 안에 신고되는 비율**. 고장 신호가 같을 때 사람들이 얼마나 신고하는지를 직접 잰다.

```sql
-- trips(또는 trips21)와 fail로
CREATE OR REPLACE TABLE sham_rep AS
SELECT t.bike_id, t.rent_dt, f.reg_ts,
       f.reg_ts IS NOT NULL AND f.reg_ts <= t.rent_dt + INTERVAL 24 HOUR AS rep24
FROM (SELECT * FROM trips WHERE rent_st = rtn_st AND use_min <= 3) t
ASOF LEFT JOIN fail f
  ON t.bike_id = f.bike_id AND f.reg_ts >= t.rent_dt;
SELECT date_trunc('month', rent_dt) AS m, avg(CAST(rep24 AS DOUBLE)) AS p_rep24, count(*) AS n
FROM sham_rep GROUP BY 1 ORDER BY 1;
```

- 2021년 신고는 시각이 없어(0시) **같은 날 또는 다음 날**로 기준을 바꾼다(`reg_ts`의 날짜 ≤ 헛대여 날짜 + 1). 두 기간 비교는 이 날짜 기준으로 맞춘다. ASOF 조건 `f.reg_ts >= t.rent_dt`도 날짜로 바꿔야 한다(0시로 기록된 같은 날 신고가 대여 시각보다 앞서서 빠진다)
- [ ] 2025-03 전후로 `p_rep24`가 약 30% 떨어지면 **신고 성향 하락**이 레짐 변화의 직접 증거
- [ ] 2021-04 전후로 `p_rep24`가 크게 오르면 같은 논리로 신고 성향 상승
- [ ] 헛대여 기준 2분·5분으로 민감도. 결론이 바뀌면 메모에 적는다

헛대여에는 고장 말고도 마음이 바뀐 대여, 잘못 뽑은 자전거가 섞여 있다. 그래서 '수준'보다 **전후 변화**를 본다.

### 프레임 형태 = 코호트 (2026-10-07 추가)

프레임이 L자형 → 탑튜브형으로 바뀌었다(누적 3.2만 대, 2025-11 기준. `events.csv` `top_tube_frame`). 2020-11 ~ 12 신형 8,000대 도입 때 "안장 아래 균열 문제 해소"가 언급됐다(`docs/reference/08` 2020-11 행). L자형은 안장 기둥이 꽂히는 부분에 균열이 생기기 쉬웠고, 이용자는 이를 "안장이 흔들린다"로 느껴 **안장으로 신고**했을 수 있다. 고장구분 값에 프레임·차체 항목은 없다(값: 기타·체인·타이어·안장·페달·단말기·파손 629건·잠금장치 251건 — `fail_std`) → 프레임 문제는 '안장' 또는 '기타'로 들어갔을 것이다.

- 프레임은 차종 자체라 기존 자전거에 달 수 없다 → 신규 구매·폐기 속도(2024년 1,300대, 2025년 2,000대)로만 바뀐다 → **몇 년에 걸친 완만한 추세**는 설명해도 2025-03의 계단형 하락(0.80배)은 설명하지 못한다. 실제로 안장의 연도 수준은 2021 → 2024에 이미 0.58배로 완만히 내려왔다(`reg_m4` 부품별, `docs/notes/03` 1B 절). 이 완만한 하락이 프레임 교체와 맞는지가 R7의 질문이고, 3월의 계단은 별개로 남는다.
- 도입 시기 ≈ 프레임 형태이므로 R7의 코호트 비교가 사실상 프레임 비교다. **안장 신고율을 코호트별로 따로** 본다. 오래된 코호트(L자형)의 안장 신고율이 뚜렷이 높고 그 코호트가 폐기로 줄어드는 속도가 안장 신고의 완만한 하락과 맞으면, "노후 차량 폐기 → 안장 신고 감소"로 설명된다.
- 한계: 연도별 탑튜브형 도입 대수가 없어 프레임 형태를 자전거별로 직접 알 수 없다. 2022-03 이후 처음 등장한 번호만 도입 시기를 믿을 수 있다(그 전은 QR 교체 때 번호가 새로 붙음).

### 폐기 기준을 함께 쓴다

공단 폐기 기준: **도입 6년 경과 + (대여 3,000회 이상 또는 운행 6,000km 이상)** → 정밀 점검 후 운행이 어려운 것만 폐기([헤럴드 2026-09](https://www.heraldk.com/article/2026091814451482547)).

- [ ] **기준 도달 시점 만들기**: `bike_year`(2015~)와 상세 적재분으로 자전거별 누적 대여 횟수·거리를 이어 붙여, 나이 6년 + 3,000회 또는 6,000km를 처음 넘은 주를 표시한다. 2020-03 ~ 2021-01 QR형 거리 0 때문에 거리 기준은 과소 → 대여 횟수 기준을 주로 쓴다
- [ ] **생존자 편향 점검**: 기준을 넘은 자전거 중 상태가 나쁜 것부터 빠지므로, 오래된 코호트일수록 남은 자전거가 '건강한 생존자'다. 코호트별 신고율 비교 전에 기간별 마지막 등장(= 폐기 추정) 대수를 같이 본다
- [ ] **구성 효과의 크기**: 2024년 폐기 1,400대, 2025년 2,000대(운영 4.5만 대의 3~4%). 폐기 대상이 평균보다 신고율이 몇 배 높았다고 가정해야 29% 감소를 만들 수 있는지 계산해, 구성 효과만으로 설명 가능한지 판단한다
- [ ] **점검 효과**: 기준 도달 → 정밀 점검을 받고 살아남은 자전거의 신고율이 도달 전후로 내려가는지
- [ ] **번호 재부여 확인(덤)**: 2020년 이후 처음 등장한 번호가 6년이 안 돼서 폐기(마지막 등장)되는 비율이 높으면, 실제로는 옛 자전거가 QR 개조 때 새 번호를 받은 것일 가능성. `신고율-변화-원인-외부자료-조사.md` 2절의 가설 (가)를 데이터로 가르는 방법이다
