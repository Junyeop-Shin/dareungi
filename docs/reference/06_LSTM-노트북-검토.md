## 결정적 발견 3가지
1. **28개 코드 셀 중 24개가 `rentals`를 예측.** `TARGET_COL = 'rentals'`가 셀 13·20·22에 선언. 셀 27에서야 부품별 고장 4종으로 전환. **`total_faults` 타깃 셀은 없음** → 보고서의 총 고장 LSTM 결과(MAE 84.6 / MAPE 29.8% / R² 0.74)는 이 노트북 산출물이 아님. 재현 경로 단절.
2. **XGBoost가 LSTM을 이겼는데 보고서에 없음.** 셀 25: XGBoost 18.50% vs LSTM 28.13% (대여량, 2023~24). 정의 셀은 삭제됨(`pred_xgb` 출처 불명). 일별 표 형태 데이터에서 트리 모형이 RNN을 이기는 표준 결과. **재수행 시 XGBoost/LightGBM 필수.**
3. **부품별 안장 모형은 7일 이동평균보다 못함.** LSTM MAE 30.8 vs MA7 28.3. 체인·타이어·페달은 나이브 대비 17~29% 개선.

## 심각한 문제 (우선순위)
- **2-1 타깃 혼재 + 보고서-코드 불일치**: 대여량 튜닝 결과(timestep 60, 2층, 유닛 96, dropout 0.5, lr 0.01)를 고장 예측에 그대로 이식. 보고서는 Dense(7) 7일 시퀀스 출력이라 서술했으나 노트북은 Dense(1) t+7 단일값. Model A/B 수치도 불일치(보고서 71→61% vs 노트북 47→45%). 실행 순서 정보 없음(`execution_count` 전부 None), 셀 21 `NameError: plt` = 비순차 실행 증거.
- **2-2 XGBoost 누락**: 가장 강한 모형을 빼고 발표. "비교했고 트리 모형이 나았다" 자체가 결과.
- **2-3 테스트셋으로 선택**: 셀 15·17·23 그리드서치·timestep 선택 모두 `CURR_X_TEST` 기준. 분할 재설정도 테스트 성능 때문. 예외: 셀 26 keras-tuner만 val_loss 기준.
- **2-4 부품별 테스트 구간 상이**: 셀 27은 학습 꼬리를 안 붙여 731→665일, 2023년 1~2월 비수기 누락. 대여량 결과와 같은 표에 놓으면 안 됨.
- **2-5 검증-학습 윈도우 중첩**: `validation_split=0.2`는 시간순 유지하나 timestep 60 윈도우가 최대 59일 겹침 → 조기종료 지연. 윈도우 생성 *전* 날짜로 분리 + 경계 gap.
- **2-6 하이퍼파라미터 경계 충돌**: tuner 결과 dropout 0.5(max), lr 0.01(max). 탐색공간 좁음. lr 0.01+RMSprop 첫 에포크 손실 3.24로 불안정.

## 핵심 수정 코드 요점
- 검증 분리: `GAP = TIMESTEP`으로 경계 간격, `validation_data=(X_va, y_va)` 사용
