# 따릉이 고장 예측 프로젝트 — 1차 분석 검토 핵심 결론

작성: 2026-09-12 / 대상: 「서울시 따릉이 고장대수 시계열 예측 프로젝트」 5조 최종보고서

## 검토 대상
- 데이터: `dareungi_master.csv` (2016-01-01~2024-12-31, 3,287행)
  컬럼: date, rentals, temp, rain(0~3 범주), humidity, solar, snow(이진), fail_saddle/chain/tire/pedal, total_faults
- 보고서: ARIMA/SARIMA/GARCH + 다중회귀 + LSTM/GRU

## 핵심 진단: "대여량 예측기였다"는 자평은 맞다
원인은 모델이 아니라 **종속변수 설계**. 대여량은 원인 변수가 아니라 노출(exposure)이므로 offset으로 내려야 함.

### 근거 1 — 만 건당 고장률이 안정적이지 않음
| 연도 | 만 건당 고장률 |
|---|---|
| 2016 | 6.8 |
| 2018 | 28.8 |
| 2021 | 47.4 |
| 2024 | 36.9 |

7배 변동. `고장 = k × 대여량`의 k가 고정이 아니며, k의 변동이 진짜 위험 신호인데 현 설계는 전부 잔차로 버림.

### 근거 2 — 노출 통제 시 설명력 소멸 (2021~2024)
| 변수 | 고장 건수 기준 ρ | 고장률 기준 ρ |
|---|---|---|
| rentals | +0.96 | +0.28 |
| temp | +0.33 | +0.22 |
| solar | +0.35 | +0.22 |
| rain | −0.13 | −0.13 |

→ 현 변수셋(일별 총 대여량 + 서울 1개 지점 기상)으로는 노출 외 요인을 잡을 수 없음. 개체 단위 확장의 논리적 근거.

### 근거 3 — Newey-West(HAC, lag=14) 재계산 결과
| 변수 | 계수 | OLS t | HAC t |
|---|---|---|---|
| rentals | 0.0044 | 124.97 | 49.78 |
| rain | 5.200 | 2.12 * | 1.55 (비유의) |
| humidity | −0.437 | −2.46 * | −1.38 (비유의) |

total_fail 모형의 유의한 기상변수 2개가 모두 소멸. rentals만 남음.

## 데이터 오류 (확인됨)
- **표 3의 solar 기술통계가 실제 CSV와 불일치**: 보고서 평균 4.301 / 중앙값 0 / 왜도 1.558 vs 실제 13.741 / 13.01 / +0.258. 회귀 계수는 올바른 데이터로 산출됨(재현 일치) → 표 3만 손상된 버전. 그에 딸린 "0 근처 집중, 우측 꼬리 긴 비대칭" 해석 문단이 사실과 반대.
- snow도 불일치(평균 0.054 vs 0.030, 눈 일수 178 vs 99).
- 표 4 fail_pedal: Adj.R²(0.8839) > R²(0.8392) — 수학적으로 불가능, 전사 오류.
- 본문 모순: 유형별 상관 절 서두 "일사량 음의 상관" vs 실제 전부 +0.32~0.35.
- 기타 고장 solar ρ=−0.724 — 다른 유형과 정반대, 재확인 필요.

## 나이브 벤치마크 (2024 테스트 구간, 보고서에 없음)
| 방법 | MAE | MAPE |
|---|---|---|
| lag-7 | 140.2 | 63.2% |
| 직전 7일 이동평균 | 129.1 | 56.8% |
| 최종 LSTM (D+7) | 84.6 | 29.8% |

LSTM이 나이브 대비 MAE 약 35% 개선 — 모델에 실질 가치 있음. 반드시 보고서에 포함할 것.

## 주요 방법론 지적
1. 카운트 데이터에 OLS → 음이항 GLM + `offset(log(rentals))`
2. 자기상관(DW 0.41~0.73) 하에서 p-value 해석 → HAC 표준오차 필수
3. rain(0~3 순서형)을 연속형 계수로 투입 → `factor(rain)` 또는 원 mm + log1p
4. 모형 간 비교 불공정: SARIMA는 730일 정적 예측, LSTM은 롤링 → rolling-origin으로 통일, SARIMAX로 정보집합 일치
5. LSTM 미래공변량이 기상 **실측값** (예보 아님) → 가정 명시 또는 예보오차 민감도 분석
6. 테스트셋으로 모델 선택(분할·timestep·하이퍼파라미터 3회) → 2023 validation / 2024 test 격리
7. SARIMA(5,1,4)(0,1,0)[365] 비현실적 → `auto.arima(xreg=cbind(fourier(ts,K=4), rentals, temp))`

## 우선순위 상위 3개 (각 반나절)
1. HAC 표준오차로 회귀 재해석
2. 나이브 벤치마크 표 추가
3. 표 3 · 표 4 오류 정정 + 데이터 버전 고정
