# 따릉이 프로젝트 전체 타당성 검토 — 요소별 6개

작성: 2026-09-27
선행 문서: 1차-분석-검토-핵심결론 / 재수행-실행계획-4주 / 추가변수-검토-실증결과 / 설계쟁점-7개-답변-및-문헌정리 / 개체단위-확장-설계안 / LSTM-노트북-검토

검토 대상 요소
1. 재수행 + 베이스라인 대비 향상도
2. 추가 데이터·파생변수
3. 목적에 맞는 모델 (LSTM 고집 X)
4. 따릉이 동향 + 국내외 공공자전거 정비·부품 수요 분석 방식
5. 자전거 1대의 현재 고장률 (주행거리·수리 이력·주행 구분·지형·날씨)
6. API 자동 수집 → 정비·부품 대시보드(서울시 제안) + 개체 대시보드 + 시민용 자전거번호 조회

---

## 결론

**진행 가능.** 기술적으로 막히는 요소는 없다. 대여이력·고장신고 모두 자전거번호가 들어간 Open API가 있다.

단, 네 가지 조건이 붙는다.
1. **여섯 개를 한 프로젝트로 보지 말고 3단계로 나눈다** — 집계 예측(1·2·3) → 개체 위험(5) → 서비스(6). 각 단계가 단독 결과물이 되게.
2. **종속변수는 '고장'이 아니라 '이용자 고장신고'다.** 실제 수거 대수는 신고의 약 2배(헤럴드경제 2026-09-19). "고장률"은 "신고 위험도"로 정직하게 정의해야 한다.
3. **수리(정비) 이력은 비공개.** 개체 모델의 "수리 후 리셋"은 추정으로 대체한다.
4. **시민용 자전거번호 조회는 이미 유사 서비스(RIDEY)가 2026-09-25 공개됐다.** 차별화 없이는 제안 가치가 낮다.

| # | 요소 | 판정 | 핵심 이유 |
|---|---|---|---|
| 1 | 베이스라인 대비 향상도 | **가능 (가장 확실)** | 1차 결과를 나이브와 비교해 보니 개선이 일관되지 않음 → 재수행 목표가 명확해짐 |
| 2 | 추가 데이터·파생변수 | **가능 (대부분 검토 완료)** | 기존 추가변수 문서 + 구조변화 변수(체인가드·기어 교체, 2025 신고 급감) + 헛대여 선행지표 |
| 3 | 목적 맞는 모델 | **가능** | 의사결정 = 센터×부품×주 단위 부품·인력 계획 → 카운트 GLM·GBM·분위수 예측. LSTM은 후보 중 하나 |
| 4 | 동향·국내외 사례 | **조사 완료** | 날씨·이용량으로 정비(신고) 수량을 예측한 연구는 못 찾음 → 기여점 |
| 5 | 자전거 1대 고장률 | **조건부 가능** | 조인 가능. 수리 이력 없음, 경로·노면 직접 관측 불가 → 프록시로 |
| 6 | API·대시보드·제안·시민 조회 | **기술 가능 / 제품·제도 조건부** | 고장신고 API 최신성 미확인, 서버 수집기 필요, 유사 서비스 존재, 재식별·책임 문제 |

## 1. 베이스라인 — 1차 결과를 나이브와 비교 (2026-09-27 계산)

조건: 2024 테스트, '향후 7일 합계' 타깃(최종보고서 표 21·22와 동일). 주간 평균이 보고서와 정확히 일치함을 확인(타이어 568.04, 체인 728.37, 안장 471.58, 페달 381.60). 예측 원점 360개(2024-01-01~12-25).

| 부품 | 나이브 '지난주 합계' MAE (MAE%) | LSTM MAE (MAE%) | GRU MAE (MAE%) | LSTM 개선율 | GRU 개선율 |
|---|---|---|---|---|---|
| 타이어 | 100.9 (17.8%) | 96.5 (17.0%) | 79.6 (14.0%) | +4.4% | +21.1% |
| 체인 | 139.0 (19.1%) | 130.9 (18.0%) | 137.9 (18.9%) | +5.8% | +0.8% |
| 안장 | 95.4 (20.2%) | 108.2 (22.9%) | 71.2 (15.1%) | **−13.4%** | +25.4% |
| 페달 | 75.6 (19.8%) | 71.6 (18.8%) | 85.7 (22.5%) | +5.3% | **−13.3%** |

- 개선율 = 1 − MAE(모델) / MAE(나이브)
- 다른 나이브(MAE%, 타이어/체인/안장/페달): 최근 4주 평균×7 = 20.5/22.1/21.7/22.8, 작년 같은 주 = 25.4/24.5/36.6/21.1 → **'지난주만큼'이 가장 강한 나이브**

해석
- 주간 총량 기준 LSTM은 나이브보다 4~6% 나음. 안장은 오히려 나쁨.
- GRU는 타이어·안장에서 20%대 개선, 페달은 나쁨. **어떤 구조도 네 부품 모두에서 나이브를 이기지 못함.**
- 1차 모델은 미래 기상 실측값(완벽 예보)을 썼고 테스트셋으로 설정을 골랐음 → 실제 격차는 더 작을 가능성.
- 일별 D+7 총량은 LSTM 84.6 vs MA7 129.1(35% 개선, 1차 검토 문서). 일별 요일 패턴은 잡지만 주 단위 수준 변화 예측력은 약하다는 뜻.

재수행 원칙
- **베이스라인 세트 고정**: 지난주 합계 / 지난주 같은 요일(snaive-7) / MA7·MA28 / 작년 같은 주 × 최근 증감률
- **지표**: 결과표 첫 열에 MASE 또는 skill score(나이브 대비 %). 재고 목적이면 분위수 손실(pinball)·예측구간 커버리지. 일별 MAPE는 0 근처에서 불안정 → wMAPE
- **평가**: rolling-origin(주 1회 원점). 학습 2020~2023 / 검증 2024 / 테스트 2025~2026H1
- **레짐 주의**: 2025 신고가 전년 대비 약 30% 감소(162,058 → 112,970, 공단). 대여는 약 15% 감소(2025 일평균 102,392). 만 건당 신고 약 36.9(2024) → 약 30(2025, 추정). 테스트 구간이 다른 레짐이라 건수 모형은 과대예측 위험 → **고장률(offset) 설계가 더 중요해짐**

## 2. 추가 데이터·파생변수

기존 검토(추가변수 문서): 요일·공휴일, 전날 강수, 기온 U자, 부품별 계절지수, 노출을 이동거리로, 운영 대수·차령, ASOS 확장, 미세먼지, 거리두기 달력 등.

오늘 추가
- **구조변화(개입) 변수** — 탑튜브형 프레임 32,000대 적용 완료, 체인가드 2025년 말 16,000대 → 2030년 전체, 8단 기어 매년 4,000대 교체 계획, 7단 기어 300대 언덕 지역 시범(2026-12 목표). 체인·변속 관련 신고 분포가 바뀔 것 → 연도별 누적 적용 비율을 연속변수로
- **플릿 구성** — 운영 약 45,000대(2023년부터 동결). 폐기 2,105/4,500/1,400/2,000, 신규 6,000/6,100/1,300/2,000(2022~2025) → 평균 차령 추정
- **요금·상품 변화** — 가족권(2025-04-23), 3시간권(2025-11-13), 기후동행카드 연계 → 이용 구성(장거리·여가) 변화
- **헛대여(빌리자마자 반납) 일별 건수** — tbCycleRentData로 집계(같은 대여소 반납 + 수 분 이내). 다음날 신고의 선행지표 후보. 개체 단위에도 그대로 사용
- **실제 예보값** — 단기예보(글피까지, 1시간), 중기예보(10일, 일 2회) → 1차의 '완벽 예보' 가정 해소. 과거 예보 아카이브 확보 가능 여부는 확인 필요
- **준실시간 노출** — OA-21229 대여소 간 5분 단위 이용 건수(매일, 5일 시차) 또는 tbCycleRentData
- 판단 기준 유지: **"노출의 또 다른 얼굴인가, 노출 통제 후에도 남는 위험 요인인가"**

## 3. 모델 — 목적에서 역산

의사결정: 정비센터 11곳(강남 6·강북 5)의 **다음 1~4주 부품 발주·정비 인력 배치**.
필요 출력: 센터(또는 관리소)×부품×주 단위 건수 + 불확실성 구간.

| 역할 | 모델 | 이유 |
|---|---|---|
| 베이스라인 | 지난주 합계, snaive-7, MA | 비교 기준 |
| 설명·주력 | 음이항 GLM + offset(log 노출) + 달력·기상·개입 변수 | 서울시에 설명 가능, 예측구간 자동 |
| 정확도 후보 | LightGBM/XGBoost (Poisson·Tweedie 목적함수, 분위수 회귀) | 표 형태 일별 데이터에서 강함. 1차 노트북에서도 XGBoost(18.5%)가 LSTM(28.1%)을 이김(대여량 기준) |
| 시계열 기준 | Fourier-ARIMA(X) / ETS | 통계 벤치마크 |
| 구조 | 2단계: 고장률 모형 × 이용량 예측 | "고장 = 이용량 × 고장률" — 설명 쉽고 레짐 변화에 강함 |
| 정합 | 계층 조정(MinT) | 전체 = Σ부품 = Σ센터 일치 |
| 선택 | LSTM/GRU | 약 2,400일(2020~2026H1) 규모는 딥러닝에 유리하지 않음. 나이브·GBM을 이기면 채택 |

센터 단위로 쪼개면 일부 부품 시계열이 간헐적 → ADI/CV²로 분류해 Croston/SBA/TSB 비교.

### 분석 목적 정의에 주는 시사점
1. 목적 문장
   - 집계: "이용자 고장신고 수요를 센터×부품×주 단위로 1~4주 앞서 예측해 부품 발주·정비 인력 배치를 지원"
   - 개체: "자전거별 신고 위험도를 산출해 점검 우선순위를 정함"
2. 세 문제를 구분: (i) 집계 수요 예측, (ii) 개체 위험(앞으로 N km·N일 내), (iii) 현재 상태 탐지(지금 고장인가). 업계도 분리 운영
3. 노출은 달력 기간이 아니라 누적 이용(횟수·km). 공단 폐기 기준도 이 방식

## 5. 자전거 1대 고장률 — 조건부 가능

데이터
- 대여이력 `tbCycleRentData`(OA-15182): BIKE_ID, RENT_DT, RTN_DT, 대여·반납 대여소, USE_MIN, USE_DST(m), 이용자종류·성별·생년, 자전거구분. 시간 단위 조회, 호출당 1,000건. 파일은 반기(2026-01~06분이 2026-07-15 등록)
- 고장신고 `tbCycleFailureReport`(OA-15644): BIKENO, REGDTTM(**YYYYMMDD, 날짜만**), 고장구분. 파일 반기
- 선례: 박원빈(2020, GitHub)이 2015~2020 데이터를 자전거번호로 조인해 개체별 이용·고장 관계를 기술 분석. 매칭률은 미공개

| 요청 | 가능성 | 방법 |
|---|---|---|
| 주행거리 | 가능 | USE_DST 누적. 0·결측 비율 점검 |
| 수리 이력 | **불가(비공개)** | 신고 후 대여 공백으로 '수거·정비됨' 추정. 공단 협업·정보공개청구 시도 가치 있음 |
| 주행 구분(출퇴근/여가) | 프록시 가능 | 시간대·요일, 왕복 여부, 대여소 168차원 프로파일 군집, 한강공원 인접 |
| 험한 지형(언덕) | 부분 가능 | 대여·반납 대여소 고도차(DEM), 우회율, 속도. 실제 경로는 모름 |
| 노면 불량 | 거의 불가 | 서울 전역 노면 데이터 없음(포트홀 데이터셋 2026-08-18 종료). 한계로 명시 |
| 날씨 좋을 때 탔는지 | 가능 | 대여 시각 × ASOS 시간자료 → 우천·혹서·혹한·비 온 다음날 주행 비율 |

출력 정의
- '현재 고장률' = "향후 7일(또는 다음 N km) 안에 신고될 확률"
- 신고 누락이 있으므로 절대 확률보다 **플릿 내 상대 등급(상위 x%)**으로 제시

모델
- 주력: 자전거×주 패널 이산시간 위험모형(LightGBM + 확률 보정) — 배포·갱신 쉬움
- 해석: Cox·Andersen-Gill — 위험비(지형·날씨·주행 구분 효과)
- 선택: DeepSurv

평가
- 시간 분할, C-index·Brier
- **precision@K**: "위험 상위 500대를 점검하면 다음 주 신고의 몇 %를 미리 잡는가"
- 베이스라인: 누적 거리 단일 모형, 과거 신고 횟수 모형

## 6. API·대시보드·제안·시민 조회

### 기술
- 수집 가능: 대여(준실시간 — 서드파티 실측상 반납 직후 반영, 미검증), 고장신고(API 최신성 **미확인** — 첫 확인 대상), 대여소 실시간 현황(bikeList: 대여소 단위 7개 필드. 개별 자전거 ID·GPS 없음), 기상(ASOS D-1, 단기·중기예보)
- 구조: **서버 쪽 수집기 필수** — 8088 포트 평문 HTTP + 인증키 노출 때문에 브라우저에서 직접 호출 금지. 스케줄러(cron·GitHub Actions) → DuckDB/Parquet 또는 Postgres → 대시보드(Streamlit·Dash 등)
- 부하: 하루 10만~15만 건 → 150회 이상 호출/일. 장애 감지·재수집 로직 필요(2026-09-25 부분 누락 사례 보고)
- 스키마: 2015~2025 대여이력 ZIP이 2026-04에 전부 재등록(사유 미상) → 연도별 헤더·자전거번호 형식 재확인

### 대시보드 1 — 정비·부품 (공단용)
- 내용: 다음 1~4주 부품별 신고 예측 + 구간, 권장 재고, 필요 인력, 헛대여 선행지표, 예측 vs 실제 추적
- 제약: 센터별 담당 구역 비공개 → 자치구 또는 강남·강북 관리소 단위로 시작

### 대시보드 2 — 개체 위험 (공단용)
- 점검 우선순위 목록, 부품별 위험, 지도

### 시민용 자전거번호 조회
- **이미 존재: RIDEY** (https://zmflm0110.github.io/ridey/app/, MIT)
  - 2026-09-25부터 5분 주기 실시간 경보, 자전거번호 조회
  - '연속 헛대여'로 미신고 고장 탐지. 자체 주장: 고장의 49~61%가 공식 신고되지 않음, 경보가 신고보다 중앙값 20~25시간 앞섬(외부 검증 없음)
- 차별화: RIDEY = (iii) "지금 고장인가" / 이 프로젝트 = (ii) "누적 마모·지형·기상 노출 기반 부품별 위험" + (i) 정비·부품 수요 예측. 시민 조회는 부가 기능, 핵심 가치는 공단용 계획 도구
- 주의점
  - **재식별**: 자전거별 대여 시각·대여소를 그대로 보여주면 특정인의 이동을 추적할 수 있음(원자료가 공개돼 있어도 조회 편의성이 위험을 키움) → 누적 거리·최근 이용 횟수·신고 이력·위험 등급 같은 **집계만** 표시, 생년·성별 제외
  - **책임**: "안전함" 표시 금지. "점검 필요 가능성" 신호 + 앱 신고 유도
  - **라이선스**: 서울시 따릉이 데이터는 공공누리 1유형(상업·변경 허용, 출처 표시 의무). 공공기관 후원·공식 서비스로 오인할 표현 금지. 에어코리아는 3유형(변경금지)

### 제안 경로
- 서울시설공단 일반제안 — 수시, 72시간 내 답변, 분기 포상
- 상상대로 서울 자유제안 — 상시, 30일 내 공감 50개 → 부서 답변
- 서울시 빅데이터 활용 경진대회 **시각화 부문(대시보드)** — 2026년은 3/16~5/13 접수, 7/6 시상(마감). 2027년도 비슷한 시기일 가능성(미확인) → 목표 일정으로 적합
- 범정부 공공데이터·AI 활용 창업경진대회(행안부) — 서울시 대회가 예선
- 설득 논리: 신고 11만 건 vs 실제 수거 약 2배, 정비 정원 60명 동결(1인당 750대), 서울 결함 사고 138건, 국가 점검기준 법안 발의 → **"인력 증원 없이 점검 우선순위로 커버리지를 높인다"**. 공단이 이미 도로·교량 예측정비를 추진 중이라 개념적 수용성 있음
