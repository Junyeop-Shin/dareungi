# 08a. 대시보드 화면 설계 (관리자 홈 + 상세 화면)

> 08 문서(단계 3B)의 화면 구성을 구체화한 설계서. 구현은 이 문서를 기준으로 하고, 08 문서와 다르면 이 문서를 따른다.
> 작성: 2026-10-08
> 선행 조건: 07 문서의 `serving/*.parquet` 스냅샷이 갱신되고 있음

> **지금 구현과 다른 점(2026-10-10 기준).** 이 문서는 2026-10-08의 설계이고, 그 뒤 화면이 여러 번 바뀌었다. 지금의 화면은 아래와 같고, 바뀐 이유는 `docs/decision_log.md`(2026-10-08 ~ 10)와 `docs/handoff_2026-10-09.md`에 있다.
> - **화면 네 개**: 한눈에 보기 · 유형별 고장 신고 예측 · 점검 대상 · 자전거 조회. 시민 조회 앱은 없앴고, 번호 조회는 담당자용 화면으로 관리자 앱에 들어갔다(위치·배수·신고 후 상태를 숨기지 않는다)
> - **예측 대상**: 전체 + 타이어·체인·안장·페달 + 단말기·기타. 화면 이름도 '부품별'이 아니라 '유형별'
> - **용어**: '예측'·'예측 구간'·'기준값(지난주와 같다고 가정)'. 확률은 %가 아니라 평균 대비 배수. 아이콘·이모지 없음
> - **머리 영역**: 제목 줄(오른쪽에 지역 선택 또는 예측 정확도) + 자료 기준 띠(자료별 기준 시각, 밀린 자료는 주황 칸). '예측 신뢰도 배지'와 큰 경고 상자는 없다
> - **홈**: KPI 네 개는 상자 없이 세로선으로 나눈 띠, 유형별 막대는 여섯 유형, 점검 권장 목록은 순위 + 배수 + 선정 사유(번호를 누르면 자전거 조회)
> - **유형별 화면**: 지역 선택 없음(예측은 서울 전체만). 준비 수량 표·대여 1,000건당 추이·요일별 히트맵은 뺐다. 정확도 표에 구간 적중, 아래에 예측 방법과 과거 기록으로 확인한 정확도
> - **점검 대상**: 목록 셋을 버튼으로 하나씩(최근 7일 고장 신고 → 점검 권장 → 대여 직후 반납 반복), 목록마다 지도(자치구 경계, 대여소 여러 곳 선택)와 CSV 내려받기. 신고 후 상태는 수리 대기 / 미조치 의심 / 재배치 후 운행
> - **자료 갱신**: 최근 신고 목록과 자전거 위치는 매시 갱신(`py/jobs/hourly.py`)

|---|---|

### 3-2. 예측 신뢰도 배지

**역할:** KPI ① 과 부품별 예측이 얼마나 믿을 만한지만 알려준다. 실측값(KPI ②)이나 별도 모형(KPI ③)에는 해당하지 않으므로 이름을 반드시 **'예측 신뢰도'**로 쓴다.

**표시:** `[아이콘] 예측 신뢰도 {등급} · 지난주 오차 {x}% · 8주 평균 {y}%  >`

**계산** (`forecast_track`, 부품 = 전체, 최근 완결 주 기준):

```python
t = track[track.part == "전체"].sort_values("week").tail(8)
last_err   = abs(t.pred.iloc[-1] - t.actual.iloc[-1]) / t.actual.iloc[-1] * 100   # 지난주 오차 %
mae_pct_8w = (abs(t.pred - t.actual) / t.actual).mean() * 100                       # 8주 평균 오차 %
improve    = 1 - abs(t.pred - t.actual).mean() / abs(t.naive - t.actual).mean()     # 나이브 대비 개선율
```

**등급:** 오차 %가 아니라 **나이브 대비 개선율**로 매긴다. 신고가 적은 겨울 주에 오차 %가 크게 튀어도 등급이 흔들리지 않게 하기 위해서다.

| 등급 | 조건 (기준값 `[결정]`, 아래는 초안) | 아이콘 | 색 |
|---|---|---|---|
| 높음 | 개선율 ≥ 20% | `circle-check` | 성공(초록) |
| 보통 | 0% ≤ 개선율 < 20% | `alert-circle` | 경고(노랑) |
| 낮음 | 개선율 < 0% (나이브보다 못함) | `alert-triangle` | 위험(빨강) + "이번 주 예측은 참고만 하세요" 문구 |

- 기록이 8주 미만이면 있는 주만 쓰고 "최근 ○주 기준"으로 표시. 2주 미만이면 배지 대신 "정확도 기록 쌓는 중"
- 마우스를 올리면(도움말) "단순 예측(지난주와 같다고 가정)보다 얼마나 정확한지로 매긴 등급입니다"
- 클릭 → 상세 ① 하단 '예측 정확도' 영역
- KPI ① 카드 라벨 옆에 같은 아이콘을 작게 붙여 배지와 연결되어 보이게 한다
- 색만으로 구분하지 않는다. 등급 글자와 아이콘을 항상 같이 쓴다

### 3-3. KPI 4개

| | KPI ① 다음 7일 예상 신고 | KPI ② 1,000대여당 신고 | KPI ③ 점검 권장 자전거 | KPI ④ 헛대여 경보 (48시간) |
|---|---|---|---|---|
| 큰 숫자 | 전체 예측 합 (건) | 지난 완결 주 신고 ÷ 대여 × 1,000 (소수 1자리) | 등급 = '점검 권장' 대수 | 최근 48시간 경보 건수 |
| 보조 줄 | 80% 구간 하한–상한 | 전주 대비 증감 | 운영 대수 대비 % | "지금 고장일 가능성" |
| 원천 | `forecast_weekly` | `weekly_actual` | `bike_risk_latest` | `alerts_live` |
| 자치구 필터 | 자치구 예측이 있으면 적용, 없으면 "서울 전체 기준" 표시 | 적용 | 적용 | 적용 |
| 이동 | 상세 ① | 상세 ① 추이·히트맵 | 상세 ② 목록 | 상세 ② 경보 목록 |
| 비고 | 신뢰도 아이콘 | 증감 색은 중립(회색). 신고율 레짐 변화 때문에 감소를 '좋음'으로 칠하지 않는다 | 06 체크포인트 H가 '미사용'이면 카드에 "개체 모형 준비 중" | 0건이면 "최근 48시간 경보 없음" |

- 숫자 형식: 천 단위 쉼표, 건수는 정수, 비율은 소수 1자리
- KPI ④는 0보다 크면 숫자를 위험색으로 표시(아이콘 `alert-triangle` 함께)

### 3-4. 부품별 다음 주 예측

- 가로 막대: 체인·타이어·안장·페달 (예측값 큰 순)
- 막대 = 예측, 막대 위 가는 선 = 80% 구간, 오른쪽 숫자 = **권장 확보 수량(구간 상단)**
- 카드 하단 한 줄: "막대 = 예측 · 선 = 80% 구간 · 숫자 = 권장 확보 수량(구간 상단, 결품 가능성 약 10%)"
- 이동: 상세 ① 준비 수량 표

### 3-5. 주간 신고 추이

- 최근 12주 + 다음 주
- 실제 = 점+실선(주색), 그 주에 냈던 예측 = 회색 점선, 다음 주 = 예측 점 + 80% 구간 띠
- 부품 전체 합계 기준. 부품별은 상세 ①에서
- 이동: 상세 ① 부품별 추이

### 3-6. 자치구별 점검 권장 (타일맵)

- 서울 25개 자치구를 같은 크기의 사각 타일로 배치(부록 A 좌표)
- 타일 안: 자치구 이름 + 점검 권장 대수
- 색: 주색 3단계(적음/중간/많음). 경계값은 전체 분포의 3분위로 자동 계산
- 타일 클릭 또는 아래 링크 → 상세 ② (해당 자치구 필터 적용)
